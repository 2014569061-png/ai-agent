# Android 全页面 UI 二次优化建议

日期：2026-10-23。此次仅评审，不修改应用。延续蓝白、局部柔光、实色圆角与左侧抽屉。

依据：上一轮精修后的 58 个入口、116 张普通 / 大字体测试渲染，以及 `android-refined-2026-10-23` 中的模拟器截图；本轮重新并排查看全部 58 张普通页面图并核对公共空状态和折叠组件。没有重新在设备上逐个操作所有状态。原生插件在隔离测试中的缺失不是设备故障，测试字体方框也不是实际手机中文显示问题。以下将可见问题和需要补充状态验收的建议区分描述。

## 总体判断

当前已经具有统一配色，但还没有统一的信息取舍。主要问题从“功能堆积”转为“过多容器、过多说明、松紧不一致”：一些页面只有一两项内容却铺满屏幕，另一些页面仍在首屏展示技术参数、多个工具栏和完整流程。蓝色、圆角和折叠本身不能解决这些问题。

上一轮有效的改动应保留：服务商已配置项优先、侧栏工具独立、Agent 参数收起、权限正文完整换行、运行详情摘要、设备检测时间。下一轮继续精修这些结构，避免重新换风格。

## 全局先改的八件事

1. **减少容器**：卡片只表达明确分组。普通信息行不必独占一张卡；表单避免白卡套浅灰输入再套小标签。一个分组内部优先用留白与分隔线。
2. **减少折叠卡**：单行高级入口用轻量展开行，只有展开内容确实独立时才使用卡片。项目位置、环境、低频工具不宜每项都是大白块。状态异常必须在摘要中可见。
3. **统一空状态的位置**：列表无数据时，空态紧接筛选区域并适度留白，不按整个剩余屏幕机械居中。避免费用、任务、日志等页出现上方大片空白、空态落在下半屏。
4. **统一页头**：一级页 26–28sp，详情页 20–22sp；副标题默认省略，只有解释对象或范围才保留。不能同屏出现标题、副标题、正文又重复说一遍。
5. **统一操作位置**：列表页一个创建入口；表单一个明确保存动作；取消通常由返回承担。顶部最多保留两个可直接识别的操作，其余放带文字的更多菜单。
6. **控制蓝色面积**：蓝色主要用于当前选择与主要操作。等待步骤、零样本指标、普通图标和装饰不要同时强调；危险色只用于真实危险或需要处理的失败。
7. **统一文字密度**：正文 15–16sp，说明 13–14sp；不要通过缩小文字把长说明塞进首屏。短摘要必须准确，授权、费用、覆盖后果保持就近完整告知。
8. **统一几何节奏**：外边距 20dp，卡内 16dp，组间 24dp，组内 8–12dp。列表自然增高，单行基础 56dp、双行约 72dp；触摸目标至少 48dp。卡片圆角 20–24dp，输入 16–18dp；不要所有元素都胶囊化。

## 侧栏、会话状态与弹层也要覆盖

| 区域 | 下一轮具体要求 |
| --- | --- |
| 侧栏 | 保留三主入口与底部我的，但品牌区、新建按钮、主入口间距再压缩；最近对话至少在首屏上半部开始出现。当前会话选中与当前主页面选中使用不同轻重，避免两个同样强的蓝块。 |
| 助手工具面板 | 六个功能不要全用同等权重；当前会话配置与管理工具分组，避免“模型与运行 / 运行与费用 / 会话与工具”理解重叠。 |
| 进行中对话 | 回答正文优先；工具过程用紧凑摘要，当前一步清楚，完成步骤可收起。计划确认和审批单独突出，不藏在过程日志中。需用长回答、多工具和暂停样例验收。 |
| 输入区与附件 | 模型胶囊限宽，附加操作统一图标；附件用缩略行，支持移除和失败重试。键盘出现后保留最近消息与发送区域。 |
| 模型与会话配置 | 模型、Agent、项目、模式有明确分组和当前值；避免为改一个字段连续进入多层面板。 |
| 计划与工具审批 | 先动作、对象、影响，再确认 / 拒绝；高级参数可展开。单次、会话、永久授权必须可辨，危险授权不能为了简洁省略。 |
| 设备动作与恢复确认 | 显示实际变更、覆盖范围与不可逆项；多项失败可单独查看原因，不用满屏红色代替解释。 |
| 编辑与新建 | 短表单用底部面板，长正文用整页；保存位置和字段错误统一，失败保留填写内容，返回保护未保存修改。 |
| 导入、导出、密码 | 目的地与范围先于确认；密码错误就近提示，处理进度明确；不能增加不存在的同步或账号能力。 |
| 语音与页面文字 | 清楚区分聆听、识别、编辑、停止；页面文字显示来源和有效性，主动作是加入草稿，过期必须提示重新读取。 |
| 文件树与预览 | 文件名优先，长路径可查看和复制；减少每项图标背景，代码保持连续画布。 |
| 环境检测与安装 | 当前目标、所需依赖、进度、下一步分层，完整日志按需查看；失败给真实恢复路径。 |
| 分支、运行预设、协作计划 | 当前选中和切换影响明确，选项使用列表，技术配置收起；不把已结束状态做成持续运行样式。 |
| 用量与上下文 | 概览、估算、未知、结算分层，单位对齐；不要重新塞回首页常驻指标栏。 |
| 更新与安装 | 版本、来源、进度与一个主要操作，发布说明按需查看，权限提示放在实际安装前。 |

## 实施与验收顺序

1. 先做四张真实效果样板：首页、任务有数据列表、项目主页、一个复杂设置页。统一密度后再传播公共规则，避免一次改全局后只看测试是否通过。
2. 第一批修首页 / 侧栏、空态位置、重复操作、页头；第二批修任务 / 项目 / 开发工具；第三批修配置 / 能力 / 数据；最后整理诊断与低频弹层。
3. 每页至少检查空、少量、较多内容三种适用状态；异步页增加加载 / 失败 / 重试。聊天另查流式输出、审批、键盘、附件和返回。
4. 使用 411dp 普通字号、360dp / 1.6 倍文字；表单加键盘，日志 / 费用加横屏。检查文字完整可读、滚动到底、按钮可达、未保存内容保留。
5. 测试通过仅代表相应断言通过。美观验收要看实际截图：是否一个主操作、标题不重复、第一屏能理解内容、无无意义卡片与大块空白。

下一轮的核心目标：让用户更快看到内容和下一步，减少装饰与入口竞争；保留目前已改善的导航和真实能力。
