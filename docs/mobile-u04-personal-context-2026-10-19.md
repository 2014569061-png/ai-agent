# U04 接续：个人上下文遗忘保护与真实 SQLite（2026-10-19）

承接晚间交接及 U05 文件动作增量。本轮完成 U04 的数据库/遗忘保护子集，**不关闭整个 U04/W16/F17，不改变 releaseReady=false**。

## 已实施

### 防回库不再只认当前完整名称

- 写入时检查当前名称的无限定词键、遗忘时的别名、历次更正名称，以及同来源提取规则。不能仅改限定词、改回旧名称或把旧别名变成名称绕过。
- 遗忘事务在删除别名/关联前保存已知名字的保护；同来源使用 `source-sha256:<digest>` 键，避免只靠可能被同名墓碑覆盖的实体指针。摘要仍属于私有数据，不是匿名化；墓碑继续包含原有归一化名称。
- 来源规则是**保守的来源级写入阻止**，不是证明两条内容是同一实体。一个文档/会话复用同一 originRef 时，其后续新提取也会要求确认；不会因此删除其他已存在条目。
- 项目 A 的遗忘不阻止项目 B；全局遗忘不能通过把对象改挂到项目来绕过。项目 ID 的空白/空串统一为全局。
- 旧 schema-32 记录仍可根据完整键及保留的更正历史阻止旧名称，无需重新生成 Drift 或升级 schema。

### 明确重添只放行一次

- `allowForgottenReentry` 只接受用户明确陈述来源，不接受推测/资料提取自行覆盖。
- 不再删除墓碑。新条目使用新 ID，旧别名、关系、历史不自动恢复；后续自动提取仍被保护。
- 手机管理页遇到命中记录后显示单独确认：“仅重新添加这一次”；取消不写入。模型/工具的 `addFromWire()` 不转发重添开关。

### 事务与授权边界

- SQLite 插入处再次检查遗忘保护，不只依赖服务层的前置查询。
- 更正/确认的版本更新和历史写入在同一事务；旧版本被拒绝或历史写失败时，不留下虚假历史/半更新。
- 遗忘事务复核版本和生命周期；迟到的遗忘不能覆盖更新后的条目。
- 已遗忘/已删除对象不能再被迟到回调附加别名或关系。页面的遗忘确认传入显示时的 expectedRevision。
- 授权资料必须是 `granted` 才能召回；默认 `not_required` 不再被误当成授权。结构化输出自行声明授予资料权限会被拒绝。**没有实现 OAuth 或真实来源授权流程**，受信任客户端 API 的授权状态仍需未来接入真实权限源。

### 清库与旧备份恢复

- 用户明确清除全部数据会清除个人上下文五张表，包括保留的遗忘原文、历史和规则。
- 当前 v1/v2 备份没有导出个人上下文。旧备份恢复显式保留本机个人上下文和较新的遗忘保护，并返回范围警告，避免清库修复使未纳入备份的数据丢失。
- 这不是个人上下文备份支持：换设备恢复仍不能从现有备份还原 F17。结果卡备份也未补齐。
