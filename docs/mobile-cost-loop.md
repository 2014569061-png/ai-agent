# 移动端费用闭环：本机阶段

## 范围

按用户选择优先推进费用闭环。私有 APK、BYOK、终端逐次审批的决定不变。不调用真实模型、不操作真机、不获取服务商账单、不部署公共或付费服务、不提交推送、不操作签名密钥。

**这是本机预算与人工核对能力，不是支付系统、服务商强制限额或自动账单签收。** 跨机费用备份/恢复尚未完成；界面已明确说明。

## 已落地

1. `UnifiedRequest` 增加仅本地使用的运行ID、逻辑请求ID、用途。聊天和后台执行传入真实持久运行ID，主请求与摘要共享运行，token预算包装保留关联；草稿单列用途。请求ID可关联重试，每个准入尝试仍有独立账本ID。不将这些字段新增到服务商请求协议。
2. `nexus_cost_request_details` 保存关联、模型/服务商配置ID、单价快照、原预留及usage。**不保存提示词、消息内容、API Key或服务商URL。** 历史缺失字段显示“未记录”，不伪造归属。
3. 状态分为 `reserved`（预留、未核实运行状态）、`pending`（待确认，继续占预算）、`settled`（usage结算估算）、`reconciled`（人工账单核对）。取消、报错、缺usage不自动释放；已观测费用高于原预留时上调占用。仅已知发送前取消可直接释放为0，另记原因。
4. 关闭硬停而允许未定价/多模态请求时，也记录费用未知，而不是跳过账本、显示免费。重新启用硬停后，本月仍有未知费用则失败关闭，须先核对。配置了文本单价也不能将多模态费用当成可靠估计。
5. 新增仪表盘“逐请求费用明细与对账”入口，保留作用域数据库注入，避免隔离测试绕过override去读真实用户数据库。明细分页，列出运行/请求/尝试及状态；读取失败不伪装成空账本。
6. 人工对账必须填写金额、非秘密核对依据并勾选已核对账单。对账不退款、不触发模型、不重试工具；同一金额不能重复按多条请求分摊。过期对话框受revision比较更新保护。金额以替换该条记录的方式修正，不作为新费用叠加。
7. `nexus_cost_reconciliations` 留下修改前后金额、原状态、依据、时间和版本。迟到的pending费用上调会令旧对账对话框失效；已核对的金额不被重复结算覆盖。
8. 仪表盘已结算费用优先取预算账本，而不是再把历史 `run_records` 加一次；无价格的未知费用不显示为0。历史运行统计仍作为无账本结果时的兼容回退。
9. 显式清除全部数据包含新增请求明细和对账依据。兼容恢复需要保留移动数据时，不清空这些记录。不在测试中清除真实数据库。
10. 对账弹窗控制器归弹窗自身State所有，在反向退场动画结束卸载后销毁，避免保存后出现controller已销毁异常。

## 仍未完成 / 假设

- 费用账本、明细和审计尚未完整纳入保险箱跨设备备份恢复，界面已提示；不能声称跨设备预算共享。
- 请求ID是本地逻辑ID，不是服务商requestId；尚未采集并自动关联服务商请求编号。人工输入的账单依据不是服务商认证证明；本轮没有访问账户、验证发票或建立自动账单API。
- 费用单位按现有配置为人民币分；用户需填写正确单价，未实现自动汇率、完整缓存/音视频/其他附加收费对账。
- 预算预留是本地保守估算，不是对任意服务商协议的数学费用上界；本地硬停不等于服务商账户限额，已经发生的收费无法回滚。
- 文件库关闭重开与并发准入测试不替代真机进程被杀、跨isolate、多设备、弱网和真实供应商账单验收。
- 主界面收敛、完整持久远程作业协议、性能/SLO及真实模型任务评测仍待继续。60条评测用例仍为未运行，测试数量不能转写成Agent成功率。
