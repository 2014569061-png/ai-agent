# 第六阶段：可写隔离子任务提案

## 已接通的运行路径

桌面聊天在启用工作区文件工具时注册 `sub_agent_edit`，外层风险为 `requiresConfirmation`，服从现有审批模式。它通过 `IsolatedEditService` 建立独立 Git worktree，再走 `BackgroundExecutionGateway` / `HeadlessExecutor` 执行文件编辑。

借鉴 [Git 官方 worktree 文档](https://git-scm.com/docs/git-worktree) 中 detached worktree 的隔离方式，使用 `worktree add --detach --no-checkout`。未复制第三方源码。创建后手动填充父工作区的当前文件字节，避免把未提交修改错误地替换为 HEAD 内容。

- 快照包含当前暂存或未暂存文件的**工作区内容**、未提交删除、未被忽略的未跟踪文件；已跟踪文件即便匹配忽略规则仍包含。
- 不改父仓库 HEAD、分支、暂存区或源码；新增的是 `.nexus/worktrees/edit-*/source`、提案报告和 Git worktree 管理记录。
- 快照建立前后复核文件集合、哈希和 HEAD；发生变化就不启动模型。
- 要求 Git 仓库根目录、有 HEAD；限 3000 个文件、32MiB 总量、单文件 1MiB。链接、子模块及无法安全快照的目标拒绝执行，不静默用旧版本代替。
- 新建 Git 过程不 checkout 文件，禁用 fsmonitor/hooks；命令输出及运行时间有上限，不调用 shell 拼接命令。

## 子任务边界

只注册 `read_file/list_directory/search_files/repo_map/write_file/edit_file/apply_patch`。所有编辑仍使用启用读前写的 `WorkspaceSandbox`；审批回调逐个检查路径，禁止越界及 `.git/.nexus` 元数据写入，包括多文件补丁和 Windows 尾随空格、点、数据流路径。

子任务不会注册终端、HTTP、删除/移动或委派工具。所有 `RunProfile.subagent` 运行跳过插件和 MCP 加载，避免仅在连接后过滤工具。模型服务请求仍按用户已配置的模型进行；这不是 OS 进程沙箱。

单次输出预算 500–8000，默认 4000；累计输入与输出预算仍为其四倍。隔离编辑最多 8 步、模型运行限 4 分钟；子任务使用独立取消令牌，向下响应父任务取消，超时不会反向取消父任务。

## 提案、冲突与后续应用

每个任务在工作区之外的同级 `proposal.json` 持久化创建时间、基线提交、文件哈希、运行状态、结果摘要及完整变更清单。工具返回报告相对路径、隔离工作区路径、前 100 项变更和截断标识。

每项变更附 `beforeHash/afterHash/operation/parentUnchanged`。模型退出后重新读取相关父文件，发现父文件已变化时标记冲突，不能把提案自动覆盖回去。失败、取消或预算耗尽也保留已产生的文件；异常报告不暴露原始内部错误。

成功状态是 `review_required`，表示待审阅提案，不表示完成父任务或验证通过。父 Agent 必须读取子工作区文件及当前父文件，审阅并通过原有编辑工具应用，再运行父工作区验证。没有自动 merge、commit 或 cherry-pick。

## 验证及剩余项

- 真实临时 Git 仓库测试覆盖 staged/unstaged 内容分离、未跟踪文件、未提交删除、忽略文件、父仓库不变、并发外部修改冲突、子任务失败保留结果、取消及大小上限。
- 工具审批测试覆盖 Git 元数据、越界路径、Windows 路径别名、多文件补丁、终端及嵌套委派拒绝。
- Headless 真实工具注册测试确认只暴露文件工具，读前写依然强制生效。
- 7 个相关测试文件共 52 项回归通过；涉及源码与测试静态分析通过。

此处完成的是**桌面单个可写隔离提案**；现有 `sub_agents` 批量并行仍是只读。暂未增加多写任务自动合并、提案 GUI、自动删除保留工作区或崩溃任务续跑。限制内快照只覆盖上述可见文件，忽略的依赖和构建产物不会复制，也不在子工作区执行构建。
