# 第五阶段：跨文件补丁及失败恢复

已完成部分沿用前四阶段。本轮把 `apply_patch` 从单文件多 hunk 扩展为多文件批次，并接上基线、审计、审阅和运行收尾。

## 工具契约

旧的 `path` / `patch` 调用兼容。新增 `files: [{path, patch}, ...]`，最多 10 个已有文件，不能混用两种形式。每个补丁最多 128Ki 字符；单文件预读最多 1MiB；批次修改前后文本合计最多 2Mi 字符。

- 每个文件必须满足既有读前写及内容哈希新鲜度要求。
- 所有路径、重复目标、补丁头、hunk 行号和上下文全部预校验；任何一个失败，都不提交其他文件。
- 本地目标符号链接拒绝替换，须使用真实文件路径。规范化路径及符号链接解析后的别名不能在同一批次重复出现。
- 全部输出先暂存到目标旁边，再复核源文件，逐个以备份和重命名方式安装。暂存内容写入后也重新读取核实。
- 本地暂存文件由原文件复制，再改内容；非 Windows 平台检查暂存文件与源文件的 mode 一致，不一致则拒绝提交。
- 提交失败时逆序恢复。只有目标不存在或仍等于本批次预期输出时才替换回原文件；遇到外部新内容不覆盖，保留备份并返回 `effect: unknown`、`unresolvedFiles`、`recoveryFiles`。
- 已提交批次的每个文件都有独立 diff、内容哈希和增删行数。回滚成功不产生虚假变更记录；回滚冲突不把预期 diff 当成实际结果。

## 闭环接线

`FileBaselineInterceptor` 在执行前保存批次所有文件的原始版本。`ChangeReviewService` 展开已提交批次的 `fileChanges`；`DevelopmentLoopFinalizer` 遇到 `needs_recovery` 则重新从工作区快照读取实际变化，并暂停自动验证及修复，将待恢复状态写入 `openIssues`。即使同轮还有其他成功编辑，也不会漏掉冲突文件。

内部 `.nexus-patch-<随机标识>.tmp/.bak` 文件不计入工作区产出快照。清理失败会返回遗留路径，恢复备份路径也进入审计元数据。

## 借鉴与边界

参考 [Aider 的 unified diff 实现](https://github.com/Aider-AI/aider/blob/main/aider/coders/udiff_coder.py) 的补丁表示和文件级处理思路；本实现继续要求严格上下文匹配，并自行实现全批次预校验和补偿回滚，没有复制其源码。

这是**可补偿的文件批次**，不是操作系统提供的跨文件原子事务：其他进程可能观察到逐个安装的中间状态。接续收尾已增加下述持久化日志恢复；文本 flush 不等同于跨文件、目录和磁盘的断电一致性保证，文件系统外部竞争也不能靠路径检查完全消除。没有宣称崩溃原子性。

本工具仍不支持批量创建、删除、重命名。桌面可写 worktree 提案和四语言候选引用图的后续状态见对应实施记录。旧真实模型报告的 `authentication` 失败记录保留不变；用户修正本地配置后，本次独立真实模型报告已通过，详见第四阶段接续验收记录。

后续更新：桌面可写 worktree 子任务已在[第六阶段](isolated-edit-2026-10-16.md)以待审阅提案方式接通；四语言候选引用图见[索引接续收尾](remaining-mechanisms-2026-10-16.md#接续收尾多语言候选引用图)，补丁恢复见下节。

## 接续收尾：持久化恢复

2026-10-16 接续核验并修补了上一轮未收尾的恢复实现：

- `PatchJournal` 在暂存前将路径及前后内容哈希写入 `.nexus/patch-journal/<id>.json`；全部安装后写入独立提交标记，再清理备份与日志。
- 进程重启后，**下一次文件写工具执行前**自动检查日志，不是应用启动瞬间的后台恢复服务。未提交批次尝试恢复旧内容；存在有效提交标记的批次保留新内容并清理已知临时文件。
- 成功恢复返回 `PATCH_RECOVERED`，本次新编辑不执行，并清除旧读前写许可；必须重新读取后再编辑。恢复冲突或日志损坏返回 `PATCH_RECOVERY_REQUIRED`，保留备份，阻断新编辑；收尾层同时阻断自动验证和自动修复。
- 提交标记损坏时，不再当成“未提交”而回滚。完整日志预检会拒绝本地目标、备份、暂存文件及父目录中的符号链接，避免恢复一个目标时先修改另一个目标。
- 写入入口和恢复入口共用安全相对路径规则，拒绝内部元数据、Windows ADS 和尾随点/空格等无法安全重放的别名。

新增 4 项回归，覆盖损坏标记、链接备份、路径别名以及真实补丁提交后清理失败再恢复。前三项在修复前复现失败，修复后通过；本机链接用例实际执行，未跳过。连同既有用例，9 个相关测试文件共 **103 项通过**，10 个源码和测试文件静态分析无问题。

仍不承诺任意断电下的原子性、跨进程恶意竞争防护或自动覆盖人工修改；不认识的状态必须留给用户确认。当前配置的真实模型故障修复验收已通过，详见[接续验收记录](runtime-controls-2026-10-16.md#接续复验真实模型与正常应用恢复)。补丁崩溃边界仍以本节的专门回归测试为证据，不将真实模型主流程验收泛化为所有故障场景均已实测。
