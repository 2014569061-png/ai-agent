## 已接入的行为

| 问题 | 本次实现 | 入口 |
| --- | --- | --- |
| 历史静默丢弃 | 在确实需要裁剪完整旧轮次时调用当前模型生成摘要；保留近期完整轮次与 system 规则。摘要作为历史数据注入，不提升为 system 指令 | `AgentExecutor` → `HistoryCompactor` |
| 工具输出只保头 | 头尾各约一半，中间显示省略字符数，避免切断 UTF-16 代理对 | `ContextWindow` |
| 编辑无新鲜度校验 | 读取时记录 SHA-256，编辑及覆盖已有文件前复核；未读取返回 `READ_REQUIRED`，外部变化返回 `REVISION_CONFLICT`，均无副作用 | 聊天和后台工具注册表共用的 `WorkspaceSandbox` |
| 自动验证入口关闭 | 新增设置项；成功开发任务、有变更、文件及终端权限均开启、非计划模式时，在本轮原工作区执行验证 | 聊天执行和任务续跑收尾 |
| 子任务失败伪装成功 | 后台失败状态转换为工具失败；异常保留诊断日志，对模型隐藏原始异常 | `_runSubAgent` → `SubAgentTool` |
| 提示词能力不实 | 明确子任务串行；验证命令依赖实际工具和授权，构建按任务需要执行 | 委派规则、任务模板 |

自动验证入口：设置 → 受控工具清单 → **开发任务完成后自动验证**。默认关闭；开启表示授权运行项目分析和测试脚本。仍要求文件和终端权限。自动收尾使用 `includeBuild: false`，结果及跳过原因继续保存到任务审查和摘要。

摘要请求不携带工具，最多 1024 输出 token，并受窗口比例进一步限制；输入也有上限，30 秒超时，不重试。用量计入运行统计，请求进入原有请求观察链。摘要不会流入助手正文。失败、空结果或预算无法容纳时保留明确的“裁剪，未生成摘要”告示。

读写版本缓存限定在工具注册表生命周期内，最多 128 个路径；淘汰后要求重读。创建新文件不要求先读，成功写入后更新已知版本。已有空文件也按覆盖处理。UI 编辑器仍沿用自己的基线机制。

## GitHub 借鉴来源

本次读取了公开页面，借鉴机制并用项目现有 Dart 架构重写，没有直接复制外部源码。

- [Codex 输出截断](https://github.com/openai/codex/blob/main/codex-rs/utils/output-truncation/src/lib.rs)：`truncate_text` 调用中间截断函数；保留输出两端。

- [Aider 主循环配置](https://github.com/Aider-AI/aider/blob/main/aider/coders/base_coder.py) 与 [验证文档](https://aider.chat/docs/usage/lint-test.html)：区分 lint、测试及其自动执行配置。

这些链接指向可变的 main，不视为不可变版本证据。原报告中 Claude Code “自动重读五个文件”、外部产品全部没有预算参数等广泛断言，本次没有进一步证实，也未作为实现前提。

## 仍然存在的边界

- 摘要不是无损存储；超长摘要输入仍会保留头尾摘录。本次没有自动重读最近文件、持久化独立摘要缓存，或实现全历史分块摘要。
- 新鲜度校验覆盖 `edit_file` 和 `write_file`；不能拦截任意终端命令修改文件。哈希复核与磁盘写入之间仍有竞态窗口，尚不是跨进程原子 compare-and-swap。部分读取可建立版本记录，不表示模型已阅读整份文件。
- 自动验证是收尾检查，尚未接通“失败反馈给模型 → 自动修复 → 重验”的循环。任务执行完成与验证通过仍是两个状态，应查看任务审查结果。停止或新运行接管时阻止后续验证步骤；已经启动的单条命令仍按原运行时的结束/超时机制退出。
- 尚未实现 patch 格式、多文件事务、repo map/符号索引、并行子 Agent 及隔离工作区、统一 UI 折叠策略表。这些需独立设计与回归，不能以本阶段修改宣称七项差距全部消除。

后续建议优先实现验证失败回灌和独立修复预算，其次引入 Dart analyzer / Tree-sitter 支撑的符号索引；并行委派应在独立工作区和结构化结果契约落实后进行。
