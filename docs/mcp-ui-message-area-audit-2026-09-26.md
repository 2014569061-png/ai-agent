## HarmonyOS 方向改造方案（只借鉴设计思路）

原则：层次靠「面」和「间距」建立，不靠描边；圆角统一且偏大；辅助信息降一级字号和对比度；
一行只放一个主信息。

| 项 | 改造 | 解决 |
| --- | --- | --- |
| S1 圆角与面 | 统一三级圆角：卡片 16，胶囊或小芯片 = 高度的一半，用户气泡 20（右下角 6）。卡片去掉描边，改用浅填充（浅色为黑 4%，深色为白 5%） | U8、U1 |
| S2 代码块 | 去掉 Markdown 外层底板，只保留 `CodeBlock` 圆角卡片；标题栏与代码区用同一个面，标题栏加 1dp 分隔 | U1 |
| S3 行内代码 | 浅填充（与卡片同色）、圆角 4、左右 3dp 内边距、等宽字体、字号为正文的 0.9 倍 | U2 |
| S4 列表 | 序号固定宽度并右对齐；列表项间距 6dp，列表整体上下间距沿用段落间距 12 | U3 |
| S5 工具消息 | 改成自适应宽度的胶囊芯片：14dp 图标 + 13sp 弱化文字，单行省略，浅填充 | U4 |
| S6 思考卡片 | 标题行改为「💡 已思考 6 秒 ⌄」，整行可点；去掉 REASONING 和重复的计时；运行中显示「进度 · 正在生成回答 00:01」 | U5 |
| S7 节奏 | 同一轮内（用户 → AI → 工具）间距 12；新一轮用户消息之前 24；进度卡片与正文之间 10 | U6 |

每一项都只改样式，不动业务逻辑。改完重新截图，前后对比，再跑 format / analyze / test / build，
一项一个 commit。
