# 检查更新功能方案(GitHub Releases)

> 版本 v1 · 待评审

## 一、目标

设置页新增「检测更新」:点击后检查 GitHub 仓库最新 Release——
- **有新版本**:弹窗展示版本号与更新说明,一键下载 APK 并拉起系统安装;
- **已是最新**:提示"当前已是最新版本";
- **失败**(断网/限流):明确报错,不静默。

`lib/infrastructure/update/update_service.dart` 已实现:

## 三、技术方案

### 3.1 服务层重构(UpdateService)

`checkUpdate()` 返回值从 `UpdateInfo?` 改为结果对象:

```dart
class UpdateCheckResult {
  final UpdateCheckStatus status; // update | upToDate | failed
  final UpdateInfo? info;         // status == update 时非空
  final String? error;            // status == failed 时的原因
}
```

要点:
- 区分异常:`DioException.connectionTimeout/errorType == connectionError` → "网络连接失败";
  HTTP 403/403 rate limit → "GitHub 访问受限,稍后再试";其余 → 原始信息。
- 请求加 `Accept: application/vnd.github+json` 头与 15s 超时;
- 当前版本号经 `PackageInfo.fromPlatform()`(现逻辑保留)。

### 3.2 设置页 UI

在设置页新增「关于与更新」SectionCard(置于"聊天背景"之后):

```
┌──────────────────────────────────┐
│ ℹ️  当前版本   1.0.0(31.4MB)      │
│ ────────────────────────────────│
│ 🔃  检测更新               >     │  ← 点击触发
│     (检测中显示转圈)              │
└──────────────────────────────────┘
```

结果交互:
- **update** → ImmersiveSheet:
  ```
  发现新版本 v1.2.0
  ── 更新说明(Release body,markdown 纯文本展示)──
  [ 下载并安装 ]        ← 下载中显示进度,完成后自动拉起系统安装
  ```
- **upToDate** → SnackBar:`当前已是最新版本 vX.Y.Z`
- **failed** → SnackBar:具体原因

### 3.3 发布约定(你侧操作)

每次发版三步:
1. `flutter build apk --release`
2. GitHub 仓库创建 Release,tag 形如 `v1.2.0`(**必须大于**手机上安装的版本号,语义化三段);
3. 上传 APK 作为 Release asset(文件名以 `.apk` 结尾即可,服务层自动识别)。

Release body 会原样显示在更新弹窗里,可写更新说明。

## 四、边界与风险

| 场景 | 行为 |
|------|------|
| 仓库为私有 | API 返回 404 → 提示"仓库不可访问";如需私有分发,后续可加 GitHub Token 设置项(本期不做) |
| GitHub 直连失败(国内网络波动) | 明确报"网络连接失败";检测与下载均可重试 |
| Release 无 APK asset | 按"已是最新"处理并在日志标注(说明发版漏传 APK) |
| 用户拒绝安装权限 | 系统安装页本身引导;REQUEST_INSTALL_PACKAGES 权限已在 Manifest |
