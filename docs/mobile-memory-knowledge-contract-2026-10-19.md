# 记忆与知识来源增量契约（2026-10-19）

**仅为 W08/F09 的增量，不表示该工作包或整版完成。** 复用 MemoryService、KnowledgeService、既有表与 BM25；无第二引擎、无新模型调用、无真机操作。

## 自动记忆注入范围

- 延用 `category=project:<id>` 的项目范围约定。未选择项目或项目 ID 为空时，只自动注入全局类别；选择项目时，注入全局加该项目，不注入其他项目。
- 范围识别对首尾空白和 project: 前缀大小写采取保守过滤，项目 ID 本身保持精确匹配。没有可信项目参数的后台调用只获得全局记忆，不再因此注入全部项目记录。
- 先过滤再计算正文 bytes、contextRevision 与预算，因此其他项目的内容变化不改变当前注入块。bytes 为符合范围的已启用正文总字节数，不承诺全部内容均在预算内注入。
- `contextRevision` 是当前可见注入候选的指纹，不可当作 memory_write 的全局 expectedRevision。显式读取的 currentRevision 仍按全体已启用记录计算；改用稳定 ID 排序及 JSON 规范化，纳入 category、sourceType、sourceConversationId，避免同时间元数据变更漏检及分隔符歧义。
- 旧版本临时 revision 会失效：写入前需重新读取；不自动重放写入，不改数据库 schema、不删除用户数据。
- **这里只修复自动注入范围，不是完整读写权限或跨项目 ACL。** 显式 memory_get/search/write 的范围、既有会话已持有的上下文、知识库项目隔离仍需独立契约与迁移。UI 管理页仍可查看用户自己的全部记忆。全局记忆开关也不是显式工具的权限撤销开关。

## 来源与本地删除

- mobile/desktop 的 agent 来源显示“助手写入”，manual 显示“手动录入”，auto 显示“自动沉淀”；未知类型不再冒充手动。
- 手机卡片展示记忆 ID、类别/范围与已有来源会话 ID，未知类型显示原值。会话 ID 不是“该会话仍存在”的验证；没有伪造可点击链接。来源不是可信认证，也不包含完整历史编辑审计。
- 修正“数据仅存本机”的误导：记录本地管理，但启用注入后会随请求发送给当前模型服务；手机/桌面同时说明。知识库也明确本地 BM25 与发送片段是两回事。来源预览时间显式使用 UTC/ISO 8601，不猜测设备时区。
- 记忆删除确认明确：删除本地记录不撤回历史消息、已发送上下文、备份或外部副本；也不阻止以后重新保存相同内容。
- 知识删除确认明确：删除本地文档和切片、使本地索引失效，不删除原导入文件，不撤回历史/已发送上下文或外部副本。继续复用原事务删除及 generation 缓存失效，不声称已经从所有历史上下文传播遗忘。

## 知识片段与来源定位

- BM25 注入块加入真实 documentId、documentName、sourceType、chunkId、零基 chunkIndex、documentUpdatedAt；正文及来源用 JSON 转义，明确是背景资料而非指令。
- 资料片段仍来自实际 KnowledgeChunks。文档不在当前本地文档集合时，不引用孤立切片。标题、来源元数据、正文和固定头部共用 1500 UTF-16 字符预算（不是 1500 字节）；过大的元数据候选跳过，没有片段时返回空串，不返回空标题。
- 文档名改变会随既有 knowledgeGeneration 使索引更新。未实现跨进程持久 generation、外部资源版本验证或来源可信认证；对抗提示注入也不能仅凭 JSON 包装宣称通过。
- 手机与桌面提供“查看本地来源与分块”：只读当前本地副本，显示来源及最多前 20 个分块；第 21 项仅用于判断是否还有更多。不是完整文档分页、不验证原文件仍存在，不产生外部链接或执行入口。
- 原“BM25 已索引”改为“BM25 按需检索”，不将落库等同于已经构建检索缓存。
- 这只是模型输入端来源可定位，**不等于回答已正确引用或点击引用已整链路验收**。没有消耗已用尽的模型测试额度。

## 1. 权限与来源

- `ScopedMemoryAccess` 持有应用选择的不可变 MemoryScope；模型参数不能替换项目或来源会话。global 读取非项目记忆；project 读取全局及本项目，新增默认写入本项目。
- chat 工具注册在首次 await 前捕获项目/会话；headless 从已存在任务解析绑定，缺失任务拒绝继续；记忆和知识的自动注入传递项目。owner/admin 无 scope 的兼容管理 API 不是模型可选的越权入口。
- `remember`、`memory_write` 为 sensitive + requiresConfirmation；沿用既有审批引擎。trusted/fullAccess 仍可能自动批准，不声称每种权限模式都逐次弹窗。
- 注入使用 JSON 编码的内容及真实本地 ID、来源类型、来源会话、UTC 更新时间，背景数据不等于指令或外部文件权威性。

## 2. 事务与并发编辑

- MemoryService CRUD 在数据库事务内判断范围/revision/逐条 expectedMemory；不存在的条目不被旧编辑复活。已有 ID 的模型写强制提供本 scope revision。
- SQLite 秒级持久时间与返回对象统一；指纹包括正文、分类、来源、启用状态、重要度等，同秒修改不会仅依赖时间判断。
- 编辑保存失败不关闭弹窗，保留草稿、错误和复制入口；取消修改需确认；删除使用 expectedMemory；设置保存失败不报成功。
- 明确拒绝/格式/冲突的工具 effect 为 none，未知写故障为 unknown，不能暗示一定没有副作用。
- 对话框使用不透明正文背景，避免底层列表文字透入。此处并不替代全应用对比度/TalkBack/键盘门禁。

## 3. 遗忘与更正保护

schema 28 新增 `memory_forget_rules`；schema 29 保留该表。复合键为规范化内容 SHA-256 与来源会话 SHA-256，另存 UTC 时间和原因；不保存被遗忘正文或原始会话 ID。哈希不是匿名化，表和备份仍按私密用户数据处理。

- 删除在同一事务中写保护规则并删除所选行；更正正文及停用条目也为旧内容保留规则。事务失败时规则和记录一起回滚。
- 规范化为 trim、连续空白折叠和小写；助手/自动写入命中指纹时拒绝，工具返回 `permissionRequired`、`reason=memory_forgotten`、effect none，不回显正文/指纹。
- 若原条目关联来源会话，则该会话后续自动写入整体关闭，包括其他条目。这是保守保护，删除确认页明确告知；不是仅依赖模型遵循“不要重学”的提示。
- 旧自动副本命中遗忘指纹后，不再由 memory_get/自动注入暴露；显式手动保存的条目仍可用，但不会清除自动重学屏障。
- 不承诺识别跨来源的任意语义改写，不撤回历史消息、此前已发送的上下文、外部副本或现有旧备份；保留这些边界提示。不是完整的模型遗忘或向量语义去重方案。
- 新备份包含规则。恢复时合并当前较新规则和备份规则，旧版不含规则的备份不会抹掉本机保护；命中规则的旧记忆跳过，恢复报告给出数量与警告。显式清空全部用户数据仍会清除规则。

## 4. 知识项目范围与索引代次

schema 29 新增 `knowledge_doc_scopes`、`knowledge_revision`：

- 旧文档无绑定，迁移后保持全局。新导入明确选择全局或现有项目，文档、分块和绑定在同一事务提交；缺失项目不能留下半条文档。
- 项目会话只检索全局和本项目。BM25 缓存按数据库对象与项目分开；引用保留独立 sourceType，不能把项目编码进来源类型。
- 所有文档、分块、范围 INSERT/UPDATE/DELETE 均由 SQLite trigger 推进持久 revision，原始 SQL 和第二数据库连接也触发。索引构建使用事务快照，复用/返回前核对持久 revision；不只依赖单 isolate 的 knowledgeGeneration。
- 文档删除清理范围绑定；无有效文档的孤立分块不会被引用。缓存使用 Expando，避免静态强引用长期保留已关闭数据库。
- 这证明了第二连接的提交失效语义；未做单独 OS 进程压力/崩溃/长时间测试，不能将第二连接等同完整跨进程验收。已装配/已发送的旧上下文仍受运行代次屏障剩余工作约束。
- 知识管理和全量搜索是用户 owner 全库视图，不等于自动注入权限；搜索项目过滤现读取真实文档绑定。来源页和移动卡片显示全局/项目范围。
- 新保险箱包含范围，恢复保持绑定而非悄悄全局化；旧保险箱无绑定时保留旧全局语义。无效范围在删除数据之前拒绝。
- 新入库标题 1–256 字符、正文最多 100 万字符、sourceType 最多 64 字符。对既存超大来源元数据仍遵守正文+来源合计 1500 字符的注入预算，不能仅输出空标题。
- 粘贴入库在实际保存成功后才关闭；失败或取消范围选择保留精确草稿，可复制、重试，放弃须确认。文件原文不删除，文件入库异常提示核实，不伪称成功。
