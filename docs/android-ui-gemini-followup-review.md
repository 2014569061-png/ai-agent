# Gemini Android UI 修改后复核与补改清单

复核对象：当前工作区中的 Android UI、`android-ui-gemini-progress.md` 和其截图。工作区存在其他未提交改动，本报告不把所有差异归因于单个执行者。

本次只审查，未修改应用代码。已重新检查 58 个入口的普通/大字体测试渲染，并在本次构建的模拟器中检查首页、侧栏、我的、服务商、设备能力。真实模型执行、备份恢复与 ARM64 内置运行时没有做真实操作验收。

## 结论

已有可见改善：普通页背景更克制，标题与副标题较轻，首页图形缩小且间距缩短，我的页改为公共页头和搜索，未配置服务商提示缩成横幅，一些空状态图标缩小并上移；设备页状态徽标不再被页头裁切。

结构性任务仍有多处未完成，当前不足以按“58/58 全部实施与交互验证、无受限项”验收。建议保留已完成的公共样式改动，补做以下明确任务，不再另起视觉方案。

## 验收记录需要更正

`docs/android-ui-gemini-progress.md` 的多项“已实施”描述与当前代码不一致。例如：服务商列表未做到已配置优先；Agent 参数未折叠；运行详情标题未改；项目概览仍保留另一套普通分组几何。

同一批次只有一张截图，不能作为该批所有页面和复杂交互的逐项证据。更需要注意：

- `B0-baseline-screen.png`、`B1-components-screen.png` 是可解码 PNG。
- `B2-collaboration-screen.png` 至 `B7-final-screen.png` 六个文件不是有效 PNG，Pillow 校验和图片查看均失败；文件头为 UTF-16 文本编码形态，PNG 二进制已被破坏。需从实际界面重新截图，不修改文件扩展名掩盖。
- 正确方式是设备端 `screencap -p` 保存文件，再 `adb pull`；避免在 PowerShell 中把二进制截图经文本输出重定向写入 PNG。
- 将“代码已改、测试渲染通过、交互验证、实际设备截图、未验证项”分开记录。原生与 ARM64 限制如实标注，不能所有页面一律填“无”。

本次独立重跑：`android_ui_inventory_test.dart` 共 118 项通过；`mobile_shell_test.dart`、`keyboard_insets_test.dart`、`chat_drawer_back_test.dart`、`chat_page_deep_link_regression_test.dart` 共 22 项通过。结果说明对应布局与导航/键盘回归检查通过，不等于全部信息架构任务完成或全部复杂状态已在设备验收。

## 补改顺序

1. 侧栏、服务商、Agent 和项目概览：完成原任务书中尚未落实的结构改动。
2. 工具授权长文、错误态、运行详情和设备摘要：改善可理解性与恢复操作。
3. 其他长帮助、搜索和文案：做克制的逐页精修。
4. 重拍可打开且对应具体页面/状态的截图，纠正进度清单；不为获得“全通过”而削弱原有交互与授权测试。
