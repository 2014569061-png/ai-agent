# Eta 参考改进：第二阶段（2026-10-20）

> 后续进展：Android 浏览器基础操作流程已在[第三阶段](eta-improvements-phase3-browser-2026-10-20.md)实现并验收。本文保留第二阶段结束时的状态。

本阶段完成质量基线修复，为后续浏览器与无障碍执行链路建立稳定起点。采用当前工作区的增量修改，保留其他未提交工作；未新增依赖、提交或推送。

## 已完成

### 运行与验收保持同一条链路

- 修复两个工作区租约测试的夹具：先建立真实任务记录，再验证租约竞争、借用及工作区隔离。恢复安全校验未放宽。
- 故障注入验收改用现有 `DevelopmentRunCompletion`：验证失败后的修复继续留在原来的运行中，不再对已经产生文件副作用的任务另起一次运行。最终验证和清理期间继续持有租约。
- `DevelopmentRunCompletion` 支持注入 finalizer；默认行为保持原样。脚本化端到端测试使用真实 Node 检查临时文件，验证一次修复、检查文件未改变及同一次运行；没有调用真实付费模型。
- 空模型响应测试补齐 Binding、偏好、临时路径和明确单价，使用本地 SSE 服务，并断言请求确实到达。HTTP 默认测试桩、未知单价硬停等问题不能再让该测试在错误位置提前结束。

### 减少页面与基础设施耦合

- 将纯 `ProviderConfig` / `ProviderType` 模型归入 domain；原 infrastructure 路径保留兼容导出，平台适配代码可继续导入。
- 将仅用于聊天组件的 `ToolHumanizer` 移入 presentation；三个组件和对应测试改用新路径，没有从 infrastructure 反向导出页面代码。
- 会话导航回调改为传递 ID。数据库查询由 `ChatController.switchConversationById` 执行；沿用原有切换代次、运行代次及 `canCommit` 检查，防止旧异步结果覆盖新选择。
- 历史页与全局搜索用于 Navigator 返回结果的既有接口保留。不存在的会话明确失败，加载状态正确退出。

| --- | ---: | ---: | ---: |
| presentation → infrastructure 直接导入 | 92 | 78 | 78 |
| presentation 数据库导入 | 26 | 21 | 22 |

没有提高门禁上限。达到上限仍说明存在后续解耦空间，不能视为页面层已经完成数据库隔离。

### 异常处理有明确结果

- 隔离编辑失败时返回 `reportPersisted`；连失败报告也无法保存时，只附加异常类型，不假设报告写入成功，不泄露异常正文。子工作区保留，父源码不应用提案。
- 无法确认工具结算时，明确保留 `ToolEffect.unknown`，不允许盲目重放。
- 语音取消失败呈现 `service_error`；旧取消操作迟到的失败不能覆盖新录音或在销毁后通知界面。
- 地图、网页地图后备入口、日历入口与分享上下文提示失败接入结构化降级日志，仅记录稳定分类与错误类型，保留原有后备行为。
- 两个事务回滚检查只捕获预期的合成异常，其他异常继续向外报告。

仍有 117 处带明确处理意图的空 catch；本次没有宣称消除所有静默降级。

补充的 Windows 报告失败用例最初把文件系统异常类型写死为 `FileSystemException`，实际为其平台专用分类 `PathAccessException`。已修正平台兼容断言并单独复核，不改变生产失败判定。历史页 ID 回调也在修改后重新验证。

全项目 `flutter analyze --no-pub` 无问题；静默异常扫描零门槛通过；修改文件通过差异空白检查。没有运行全量测试或真实模型验收，不能据此声称整个 CI 或浏览器/GUI 能力已经验收。

现有 `Nexus_Preview_API_36` / `emulator-5554` 调试会话已热重启，终端确认 `Restart complete`。检查了助手页与任务页，任务页实际出现收件箱和最近任务入口，随后返回助手页；预览进程保持运行。x86_64 模拟器不作为 ARM64 Alpine/PRoot 真机验收证据。

## 接下来按差距推进

1. **浏览器完整操作流程。** 先做独立会话、导航和正文观察，再补 DOM 定位及交互。验收必须覆盖页面变化后旧节点失效、审批后执行、用户接管、停止与清理；先用本地固定页面验证，再连接真实网站。
2. **无障碍 GUI 操作流程。** 从用户显式启用的观察入口开始，加入窗口与节点新鲜度、动作审批、执行后读回、暂停与停止。必须区分节点不存在、界面已变化和权限缺失，避免直接重复动作。
3. **数据适配与可靠性。** 按 Android 版本和设备能力提供系统数据适配，明确当前可用范围；逐步将任务、结果与诊断页面的数据查询迁到应用服务，继续降低上述 78/21 两项依赖数量。

这些仍是与 Eta 对比时的实质能力差距。本轮完成的是可靠性与代码边界治理，浏览器 DOM 控制、完整 GUI 自动化及 ROM 私有数据适配仍待实现。
