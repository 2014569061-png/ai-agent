### 0.2 迁移验证的前提

- **不要卸载**旧版本。先在手机上保留一个**改造前**版本（schema ≤ 25），并在里面准备好数据：
  - 至少 3 个会话，其中 1 个含图片附件、1 个含工具调用；
  - 至少 1 个开发任务、1 个定时任务。
- 然后用新版本**覆盖安装**。
- 覆盖前建议先在应用里做一次备份（设置 → 数据管理）。

### 0.3 导出数据库（仅 debug 包可用）

在 Windows 上请用 **cmd.exe**，不要用 PowerShell：PowerShell 的 `>` 会改写二进制内容，导出的数据库会损坏。

```bat
adb exec-out run-as com.nexusagent.app.debug cat app_flutter/mobile_agent.sqlite > nexus.sqlite
```

然后在电脑上用 `sqlite3 nexus.sqlite`（或 DB Browser for SQLite）执行下文的 SQL。

### 0.4 查看会话日志相关的应用日志

设置 → 扩展与环境 → 用量与可观测性 → 诊断日志 → 右上角筛选 → 分类选「**会话日志**」（本次新增的筛选项）。

## B. 会话日志双写（debug 包）

每一项做完后导出数据库检查。常用 SQL：

```sql
-- 某个会话的事件流
SELECT seq, type, run_id, json_extract(payload_json,'$.status') AS status
FROM session_events WHERE conversation_id = '<会话id>' ORDER BY seq;

-- turn/end 状态分布
SELECT json_extract(payload_json,'$.status') AS status, count(*)
FROM session_events WHERE type = 'turn/end' GROUP BY 1;
```

| # | 操作 | 预期 |
| --- | --- | --- |
| B1 | 新建会话，普通问答一轮 | 以 `turn/start` 开始，中间有 `message` 和 `request/sent`，最后是 `turn/end(completed)` |
| B2 | 同一会话再问一轮 | 上一轮的消息**不会**再写一遍 `message`（按内容去重），`request/sent` 用序号引用它们 |
| B3 | Agent 模式，触发读写文件的工具调用 | 工具调用和结果都作为 `message` 事件出现；大块输出进入 `session_blobs` |
| B4 | 发送一张图片 | 正常回复；日志中有图片消息 |
| B5 | 运行中点「停止」 | `turn/end(cancelled)` |
| B6 | 触发预算暂停（步数/Token 上限），再继续 | 先是 `turn/end(paused)`，继续后开始新的 `turn/start` |
| B7 | 填一个错误的 API Key 再发送 | 界面报鉴权错误；`turn/end(failed)` |
| B8 | 开发任务在后台运行 | 日志写在 `conversation_id = 'task:<任务id>'` 下 |
| B9 | **release 包**（双写关闭）重复 B1–B3 | 功能正常；`session_events` 表**不再新增**行 |
