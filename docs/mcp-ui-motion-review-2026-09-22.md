# NEXUS Agent：下一轮 UI 与动效优化建议

日期：2026-09-22

## 1. 结论与证据边界

当前项目不是缺少 UI 组件或动画体系，而是需要把已有设计规范、设置开关与实际交互闭合，并减少视觉和渲染负担。建议顺序是：**先修体验逻辑 → 收敛聊天主界面 → 精修关键动效 → 真机 Profile 验收**，不建议先增加更多模糊、光晕或循环动画。

本轮检查了当前源码与仓库内三张既有真机截图：

- `device-check/20260922-fix/11-final-b.png`：浅色聊天页。
- `device-check/g3-settings.png`：深色设置页。
- `device-check/g7-metrics-liquid-dark.png`：深色会话指标面板。

这些不是本轮新录制的画面；静态截图只能支持布局、层级与视觉观察，不能证明动画流畅度。本轮未修改应用源码，未启动/安装应用、执行新对话或进行 Profile 性能测试。只保存审查文档与截图提取证据。以下分别标明代码事实、设计建议和待实测项目。

- `lib/presentation/motion/nexus_motion.dart`、`motion_preferences.dart`、`nexus_page_route_factory.dart` 已提供动效工具、系统减弱动态效果适配与路由。

- 聊天列表已有惰性构建、历史窗口、消息复用与仅新消息的一次性入场；`StreamingMarkdown` 已缓存稳定段落并单独更新尾部。

- 玻璃界面已有分组、移动端默认磨砂、shader 回退，以及路由防闪和下层绘制保护。

## 3. 优先修正的具体代码问题

### A1. 动效等级设置尚未接入实际动效策略

**代码事实**：外观页展示完整、节能、关闭三档，并调用 `AppAppearanceController.setEffects()` 保存。当前 `lib` 内对 `effects` / 持久化键的检索仅发现设置页和控制器的读写。`lib/main.dart:150–200` 监听玻璃、主题、语言和字体，没有监听动效等级；`motion_preferences.dart:5–8` 只读取系统 `MediaQuery.disableAnimations`。

因此，应用自己的“关闭动效 / 节能平滑”还没有控制全局动画；这应优先于新增动画。

**建议**：统一一个有效动效策略，合并系统无障碍设置与应用选择。系统要求减弱动态效果时不能被“完整动效”覆盖。区分：

- 完整：保留现有克制动效。
- 节能：保留必要的短淡入与状态反馈，减少大面积位移、折射和模糊。
- 关闭：程序性动画即时结束，关闭装饰性循环，但保留清晰的静态进度、焦点和用户直接滚动能力。

同时接入 route/sheet 的真实时长、程序性滚动和 ticker 生命周期，不能只在 transition builder 中返回静态 child。

**验收**：切换即时生效、重启保持、覆盖全部主要页面，三档与系统减弱动态效果组合测试。

### A2. 纯扁平选项与强度滑块取值冲突

**代码事实**：`appearance_theme_page.dart:151–156` 的 Slider 最小值为 `0.2`，但同页 `:283–289` 的“纯扁平”写入 `0.0`。重新构建时产生 Slider 取值越界；Debug 下存在明确的断言触发条件。本轮是源码发现，未在设备上点击复现。

此外，控制器 `app_appearance_controller.dart:24–28` 以 `0.1/0.5` 划分材质，设置页以 `0.1/0.6` 表示选中态，边界也不一致。当前百分比主要用于解析材质枚举，应审查“20%–100% 强度”的显示是否对应真实连续渲染参数。

**建议**：材质选择与强度拆开，或者采用同一枚举/阈值；Flat 时隐藏/禁用强度滑块，或让合法范围包含 0。不要只给 Slider 的显示值强行 clamp，造成界面与实际设置不一致。

**验收**：液态→磨砂→Flat→重启→重开设置，均无异常；边界值与选中态一致。

### A3. 隐藏动画不等于停止动画控制器

**代码事实**：

- `nexus_loading_skeleton.dart:24–45` 在初始化中无条件 `repeat()`；减弱动态效果只让 build 返回静态内容。
- `nexus_execution_status.dart:55–96` 的 pulse 是否启动只由执行状态决定；显示层另外检查 reduceMotion。
- `floating_capsule_input.dart:132–134、466–478` 的输入区 padding 与发送/停止切换直接使用固定时长；`session_metrics_sheet.dart:167–168` 的 tab 切换同样如此。
- `chat_scroll_coordinator.dart:111–149` 的程序性滚动使用固定 260/180ms；`chat_message_list.dart:143–168` 的定位滚动未读取动效偏好。

**建议**：偏好改变时实际 stop/reset/restart 控制器；页面不可见和应用进入后台时也正确暂停。程序性滚动在关闭/减弱模式采用合适的即时定位，不能只改返回最新按钮自身的淡入动画。

**验收**：减弱模式下循环控制器不再处于重复运行状态；切到别页/后台后无无意义 ticker；停止后仍能表达运行状态。功耗和帧耗时改善需实测，不能由源码直接推导具体数值。

### A4. 消除“看起来能点但没有操作”的卡片

`lib/presentation/dashboard/widgets/kpi_card_grid.dart:54–65` 的缓存命中率卡片仍传入 `onTap: () {}`；`nexus_metric_tile.dart:129–146` 会据此赋予交互外观。

**建议**：接到缓存解释或筛选详情；若没有详情，则使用真正不可点击的展示态，保留已有 explanation。不要给没有动作的区域加按压缩放或触觉反馈。

## 4. 视觉与交互建议（基于既有截图，不是故障断言）

| 优先级 | 区域 | 建议 |
|---|---|---|
| 高 | 聊天页信息层级 | 会话名、当前模型/模式、正文、输入形成清晰层级；上下文细项、轮数、步骤和计时不必同时占据多个常驻条，默认收敛到一个运行摘要入口，异常/待审批才强调 |
| 高 | 空闲输入区 | 保留一个明确的发送/停止主动作；空闲时收紧高度，附件、技能和多行输入出现时再增长；低频控制收进有名称的工具面板，保留 48dp 命中区与已有 Tooltip/语义 |
| 高 | 助手消息 | 短回复不需要和长回复一样强的卡片边界与动作占位；正文优先，复制、重试等次级操作降低视觉权重但保持可发现性，不要求只能长按才能找到 |
| 中 | 深色玻璃层级 | 既有设置截图中，多张卡片同时出现亮边和大面积高光；保留品牌玻璃风格，优先用在顶部、输入区、弹层外壳，普通内容卡弱化描边与高光，避免层层强调 |
| 中 | 指标面板 | 默认只呈现上下文占用、真实输入/输出、耗时和状态；步骤、事件、原始内容等保留为次级诊断入口，减少首屏筛选控件占比；简略指标与详情共用“已测量/估算/未记录”的展示语义 |
| 中 | 执行与审批 | 将准备、生成、工具执行、等待批准、完成、失败表达为稳定位置的状态变化；等待批准必须明显可操作，失败保留上下文和重试入口，不靠持续闪烁表示重要性 |
| 中 | 空态与恢复 | 复用现有骨架/空态/错误组件，保证刷新保留旧内容；已知进度用真实进度，未知进度用阶段说明，不制造虚假百分比 |
| 中 | 导航与弹层 | 目前仍有少量 MaterialPageRoute 与多处原生 modal sheet。逐项统一层级、返回/拖拽关闭规则和遮罩节奏；需要原生或专门滚动行为的弹层可以保留，不做机械全量替换 |

界面方向建议：**聊天区安静、操作区明确、运行过程可见、复杂诊断按需展开**。不建议恢复多余底部导航，也不建议通过增加阴影、粒子、打字机效果来体现“高级感”。

## 5. 动画应如何精修

优先复用现有 token，而不是引入第二套时长：

| 场景 | 建议行为 | 当前可复用时长 |
|---|---|---|
| 按钮按下/释放 | 小幅缩放或背景变化，不改变布局；无动作则不响应 | 100ms |
| 发送↔停止、状态图标 | 局部交叉淡入，主按钮位置固定，避免多处同时跳动 | 150ms |
| 新消息 | 仅首次新增时淡入+固定约 4–8dp 位移；流式文字不重复入场 | 220ms |
| 推理/工具详情展开 | 用户触发时平滑改变高度，流式内容更新不要逐 token 动画化尺寸 | 220–300ms |
| 页面进入/返回 | 保留现有轻量路线，进入稍慢、退出更快；不让背景页与前景玻璃叠画 | 250/180ms |
| Sheet | 手势跟手，松手后再完成或回弹；减弱模式即时或使用低运动版本 | 300ms |
| 指标 | 值更新局部刷新，数字宽度稳定；不对每个 token 触发滚动数字动画 | 按需，不常驻循环 |

`chat_message_list.dart:454–457` 当前新消息位移使用 `Offset(0, 0.025)`，其距离随气泡高度增长。可改为固定逻辑像素，让短消息和超长消息的“轻微入场”幅度一致。保留现有“不为历史分页/流式尾部重复播放”的逻辑。

键盘出现、输入框增高、消息追尾应被视为一套交互：避免分别启动三个布局动画；用户上翻时保持阅读位置，回到末尾由明确操作触发。不要为了“更顺滑”给每次 token 更新都加 animateTo。

## 6. 性能、无障碍与视觉验收

### 必须实测的性能项

目前不能给出实际 FPS 或掉帧率。既有 Debug 构建与 1147 项测试通过属于上一轮验证，不等于 UI 性能合格。本轮在 `test/` 未检索到常见 golden/FrameTiming 采集入口，项目根没有 `integration_test/` 目录；这是本轮检索范围内的情况，不等于断言所有外部测试均不存在。

建议建立 Profile 真机基线，覆盖：长聊天滚动、连续流式输出、长代码/表格/公式、打开/关闭玻璃 Sheet、往返设置页、键盘开合和会话切换。冷首次与暖重复场景分开记录 UI 与 Raster 的 P50/P95/P99、超预算帧数和峰值内存。

- 60Hz 帧预算约 16.7ms；120Hz 约 8.3ms。按测试设备实际刷新率分别看 UI/Raster 阶段，不把两者时长简单相加，也不承诺所有设备达到 120FPS。
- 优先减少重绘面积、隐藏页 ticker、重复解析及同时可见的复杂玻璃层；已有局部刷新和缓存要保留。
- 用真实瓶颈决定是否预热 shader、降级某层玻璃或拆分 repaint boundary，不盲目包一层 RepaintBoundary 就当优化完成。

### 无障碍与视觉回归

- 保留现有 48dp 点击区和语义，补输入区、审批弹层及运行状态的端到端读屏检查；流式输出不应逐 token 抢占播报。
- 扩展到 320/360/390dp、横屏/平板、系统大字体及应用字体叠加；已有测试涉及 1.0/1.3/1.5，但应覆盖关键路径到约 2.0 倍的可用性。
- `main.dart:175–179` 把系统 `TextScaler` 在 1.0 上采样再改成线性比例，会丢失非线性缩放行为。建议保留系统 TextScaler 的曲线，再组合应用字体偏好，而不是直接取一个比例替代它。
- 浅色、深色、高对比及自定义背景都检查正文和辅助信息对比度；正文按至少 4.5:1、关键非文本控件按至少 3:1 设验收目标，不能仅凭截图断言已达标。
- 增加主要页面的视觉快照：聊天空态/流式/停止/失败、输入键盘开/关、三种材质、三档动效、设置和指标弹层。保留 `route_transition_paint_test.dart` 中已有的转场防闪保护。

## 7. 推荐实施顺序

1. **体验逻辑小修**：接通全局动效等级；修复 Flat/Slider 冲突及材质阈值；停止无用 ticker；消除空点击卡片，并补回归。
2. **聊天主路径精修**：信息分层、空闲输入区、发送/停止、一次性新消息入场、键盘与滚动协同。先改高频场景，不扩张新功能。
3. **视觉统一与验收**：设置页玻璃降噪、指标面板分层、弹层规则收敛、视觉快照和 Profile 真机基线。

这比全站重新设计或一次性叠加更多动画，更容易得到可见且稳定的改善。实际实施应逐批提交可审查差异，并保留上一轮的数据与安全修复。
