# NEXUS 悬浮玻璃胶囊通知技术方案（FloatingToast 可交互化升级）

> 目标：把 `FloatingToast` 从「纯文本、3 秒自动消失」的轻提示，升级为参考截图（ZCode 桌面端错误条）同款的可交互玻璃胶囊：**左侧语义图标 + 左对齐文案 + 右侧操作按钮（chip）+ 关闭 ×**，错误类常驻、点 × 才消失。
> 基线：v0.6.0（+60），`flutter analyze` 0 问题、104 测试全绿。
> 原则：**不新造设计系统** —— 材质复用 `ImmersiveSurface`，节奏复用 `AppTokens`，颜色复用 `AppTheme`/`AppSemanticColors`，文案复用 `error_humanizer`，动效在现有 `AnimationController` 上做增量。

---

## 一、目标效果拆解（对照参考截图）

截图材质是标准四层玻璃，逐层映射到项目现有 token：

| 层 | 截图参数（目测） | 项目对应 | 结论 |
|---|---|---|---|
| 背景实时模糊 | blur ≈ 20–30px | `AppTokens.blurSigma(thick) = 22`（immersive_surface.dart:61 `BackdropFilter`） | 直接用 `thick` |
| 半透明填充 | 近白 α≈0.70 | `surfaceOpacity(thick, light) = .75` / dark `.65` | 直接用；想更透可微调到 .68（P2 可选） |
| 发丝描边 + 顶部高光 | 1px 半透明 | `Border.all(color: border.withValues(alpha: .78))`（immersive_surface.dart:53） | 直接用 |
| 悬浮投影 | 双层柔影 | `AppTheme.floatingShadow(isDark)`（app_theme.dart:36，黑 8%/24blur + 品牌光晕） | `showGlow: true` 即可 |

圆角：截图 ≈16px，但品牌体系 `AppTokens.capsuleRadius = 24` 且 FloatingToast 已在用 —— **保持 24，不为单个组件造 token**。

布局结构（截图 → 目标组件树）：

```
┌──────────────────────────────────────────────────────────────┐
│ (i)  Model request failed.        [⧉ 复制] [反馈问题]    ✕   │  ← ImmersiveSurface(thick, capsuleRadius, showGlow)
└──────────────────────────────────────────────────────────────┘
   ↑ 图标+语义色        ↑ 左对齐文案      ↑ GlassChip×n      ↑ 关闭
```

与现状的差异只有三处：**内容结构**（图标/按钮/关闭）、**驻留策略**（错误常驻）、**接线**（错误路径换用新 API）。材质层零改动。

## 二、现状盘点

| 资产 | 位置 | 现状 |
|---|---|---|
| `ImmersiveSurface` | `lib/presentation/widgets/immersive_surface.dart` | 四层材质齐备；`disableAnimations` 时自动降级为不透明（:41）；阴影画在裁剪层外（:71） |
| `FloatingToast` | `lib/presentation/widgets/floating_toast.dart` | 单例 OverlayEntry、顶部安全区下 88px、maxWidth 480、**替换不堆叠**、220ms 淡入淡出、点胶囊任意处消失、3s 自动消失。仅纯文本居中，无图标/按钮/关闭 |
| `ImmersiveMotion` | `lib/presentation/widgets/immersive_motion.dart` | fadeIn/scaleIn/expand，内置 reduced-motion 感知（本次可不依赖，现有 controller 够用） |
| `error_humanizer` | `lib/application/error_humanizer.dart` | `humanizeError(raw) → HumanizedError{summary, detail}`、`splitErrorDetail`、`kErrorDetailMarker` |
| 调用点 | 全库 14 处 `FloatingToast.show` | 成功类（「已复制」「已导出」）与失败类（「分享失败」「无法获取图片」、语音错误）混用同一形态 |

**Gap 汇总**：① 无语义级别（成功/失败一个样）；② 无操作按钮与关闭；③ 错误也 3 秒即逝；④ 无图标。均为 `floating_toast.dart` 单文件内的结构性扩展，不动材质层。

## 三、技术设计

### 3.1 通知语义：`ToastTone`

```dart
/// presentation/widgets/floating_toast.dart 内新增
enum ToastTone { neutral, success, warning, danger }

extension _ToneStyle on ToastTone {
  IconData? get icon => switch (this) {
        ToastTone.neutral => null, // 保持旧观感：无图标
        ToastTone.success => Icons.check_circle_rounded,
        ToastTone.warning => Icons.warning_amber_rounded,
        ToastTone.danger => Icons.error_outline_rounded,
      };
  Color accent(bool isDark) => switch (this) {
        ToastTone.neutral => isDark ? AppTheme.darkSemantic.onGlass : AppTheme.lightSemantic.onGlass,
        ToastTone.success => AppTheme.success,
        ToastTone.warning => AppTheme.warning,
        ToastTone.danger => AppTheme.danger,
      };
}
```

- 颜色全部取自 `AppTheme`（app_theme.dart:18-20 的 `danger/warning/success`），不引入新色。
- `neutral` 显式定义为「无图标」——保证 14 个存量调用点渲染结果与升级前**逐像素一致**，回归成本为零。

### 3.2 API 升级（完全向后兼容）

```dart
class FloatingToast {
  /// 存量签名不动，新增全部可选参数。
  static void show(
    BuildContext context,
    String message, {
    ToastTone tone = ToastTone.neutral,
    String? detail,                       // 复制按钮可拿到的完整技术细节
    List<FloatingCapsuleAction>? actions, // 自定义操作；error() 会自动补「复制」
    bool? persistent,                     // null 时按 tone 推导（见 3.5）
  });

  /// 错误便捷入口：自动 humanize + 自动「复制详情」chip + 常驻。
  static void error(
    BuildContext context,
    String summary, {
    String? rawDetail,
    VoidCallback? onFeedback, // 反馈动作接线点，见 §四 开放问题
  }) {
    // actions 默认 = [复制 rawDetail ?? summary] + 可选[反馈问题]
  }
}

/// 胶囊右侧的操作项。
class FloatingCapsuleAction {
  const FloatingCapsuleAction({
    required this.label,
    required this.onPressed,
    this.icon,
    this.dismissOnTap = true, // 反馈类动作可能想先关掉再跳转
  });
  final String label;
  final VoidCallback onPressed;
  final IconData? icon;
  final bool dismissOnTap;
}
```

`_ToastEntryController` 增加同名字段透传（替换策略不变：新 toast 顶掉旧 toast，controller 携带新参数重建 `_ToastView`）。

### 3.3 `GlassChip`（新组件，全局清单登记）

截图里「复制/反馈问题」的子按钮材质：比容器更实的浅灰填充 + 细描边 + 小圆角。独立成公共组件，后续 sheet/drawer 内的轻操作也能复用。

```dart
/// lib/presentation/widgets/glass_chip.dart（新文件）
class GlassChip extends StatelessWidget {
  const GlassChip({super.key, required this.label, this.icon, this.onPressed});
  @override
  Widget build(BuildContext context) {
    final isDark = Theme.of(context).brightness == Brightness.dark;
    final border = isDark ? AppTheme.darkBorder : AppTheme.lightBorder;
    return Material(
      color: isDark
          ? Colors.white.withValues(alpha: .07)
          : Colors.black.withValues(alpha: .05),
      shape: RoundedRectangleBorder(
        borderRadius: BorderRadius.circular(AppTokens.smallControlRadius), // 14
        side: BorderSide(color: border.withValues(alpha: .5)),
      ),
      child: InkWell(
        borderRadius: BorderRadius.circular(AppTokens.smallControlRadius),
        onTap: onPressed,
        child: ConstrainedBox(
          constraints: const BoxConstraints(minHeight: 36), // 视觉 36；语义目标 ≥44 由外层 padding 补足
          child: Padding(
            padding: const EdgeInsets.symmetric(horizontal: 12, vertical: 7),
            child: Row(mainAxisSize: MainAxisSize.min, children: [
              if (icon != null) ...[Icon(icon, size: 14), const SizedBox(width: 4)],
              Text(label, style: const TextStyle(fontSize: 13, fontWeight: FontWeight.w600)),
            ]),
          ),
        ),
      ),
    );
  }
}
```

- 填充比 `surfaceOpacity(thick)` 更实一档（黑 5% / 白 7%），对应截图「chip 比胶囊暗半档」的层次感；色值走黑白透明而非新 token。
- 已在 `Material` 子树内（floating_toast.dart:160 现有包裹），`InkWell` 水波纹直接可用。

### 3.4 胶囊布局

替换 `_ToastView` 现有单 `Text`：

```dart
child: ImmersiveSurface(
  level: ImmersiveMaterialLevel.thick,
  borderRadius: BorderRadius.circular(AppTokens.capsuleRadius),
  showGlow: true,
  padding: const EdgeInsets.fromLTRB(16, 10, 8, 10), // 右侧留给关闭键
  child: Row(children: [
    if (tone != ToastTone.neutral) ...[
      Icon(tone.icon, size: 18, color: tone.accent(isDark)),
      const SizedBox(width: 10),
    ],
    Expanded(
      child: Text(message,
          style: TextStyle(color: textColor, fontSize: 14, height: 1.4,
              fontWeight: FontWeight.w600),
          maxLines: 3, overflow: TextOverflow.ellipsis),
    ),
    if (actions.isNotEmpty)
      Padding(
        padding: const EdgeInsets.only(left: 8),
        child: Wrap(
          spacing: 8,
          children: [for (final a in actions!) GlassChip(label: a.label, icon: a.icon, onPressed: () => _onAction(a))],
        ),
      ),
    if (persistent)
      IconButton(                       // 仅常驻时出现，视觉与截图 ✕ 对齐
        visualDensity: VisualDensity.compact,
        tooltip: '关闭',
        icon: const Icon(Icons.close_rounded, size: 18),
        onPressed: _dismiss,
      ),
  ]),
),
```

要点：
- `actions` 用 `Wrap` 而非 `Row`：大字号（textScale 1.3+）时 chip 自动换行，避免 RenderFlex 溢出；约定单条 toast **最多 2 个 action**（error() 默认就 1–2 个）。
- 消息从居中改左对齐：`Row` 内 `Expanded` 天然左对齐，与截图一致；`neutral` 无图标无按钮时视觉宽度变化可忽略（文本仍近似居中，因胶囊按内容收缩 + 外层 `Center`）。

### 3.5 驻留与替换策略

| tone | 自动消失 | 关闭方式 |
|---|---|---|
| neutral / success | 3s（现状不变） | 自动 / 点胶囊 |
| warning / danger | **不自动消失**（`persistent` 默认推导） | 仅 × 与 action（`dismissOnTap: true` 时） |

- 「点胶囊任意处消失」仅对非 persistent 生效；persistent 时 `GestureDetector` 降级为 `HitTestBehavior.translucent` 只吃 action 命中，避免误触吞掉复制/反馈。
- 替换不堆叠的现有策略保持：新 toast（含错误）顶掉旧 toast。若错误与成功提示高频交替，错误可能被顶掉——接受此行为，理由见 §八。

### 3.6 动效

在现有 `AnimationController`（220ms）上做增量，不引入新控制器：

```dart
// _ToastViewState 增加 slide；复用同一个 _controller
late final Animation<Offset> _slide = Tween(
  begin: const Offset(0, -.12), end: Offset.zero,
).animate(CurvedAnimation(parent: _controller, curve: AppTokens.curveStandard));

// build: FadeTransition 外再包 SlideTransition（位移量 = 胶囊高度的 12%，轻落感）
```

- 退出沿用 `controller.reverse()`，时长已由 `durationBase=220ms` 覆盖，符合 `AppTokens` 节奏。
- `ImmersiveSurface` 内部已有 `disableAnimations` 降级（模糊关、材质转不透明）；slide/fade 跟随系统 reduced-motion 的需求由 `_ReducedAware` 模式兜底，本次不在 P0 强求。

### 3.7 无障碍与文本缩放

- 胶囊整体包 `Semantics(liveRegion: true, label: message)`：错误出现时 TalkBack 主动播报。
- × 与 chip 的命中区：`IconButton` 默认 48dp 已达标；`GlassChip` 视觉高 36 + 垂直 padding，实测 ≥44，写入组件 doc 注释作为约束。
- 图标均带 `semanticLabel`（复用 label 文案）；纯装饰的 × 有 tooltip。
- 对比度：danger/warning/success 仅用于图标（非文本，WCAG 3:1 线：`E5484D` 在浅玻璃上 ≈4.0:1 ✓）；正文始终 `onGlass`（浅 `1E293B` / 深 `FFFFFF`）✓。

### 3.8 性能与降级

- 全屏同时**只有 1 个** BackdropFilter 实例（替换策略保证），saveLayer 成本可控；清单页/列表项不引入毛玻璃的既有约束不变。
- 低端机 / `disableAnimations`：`ImmersiveSurface` 已自动转不透明底色，胶囊退化为普通悬浮条，信息不丢。
- 键盘弹起不影响：定位在顶部安全区 + 88px（floating_toast.dart:19），不在底部 insets 作用域内。

## 四、错误接线（组件落地后的第二步）

现有 14 个调用点分两类处理：

| 调用点 | 现文案 | 处理 |
|---|---|---|
| chat_page.dart:280 「图片分享解析失败」 | 失败 | 换 `FloatingToast.error`，rawDetail 透出异常串 |
| chat_page.dart:352 「分享失败」 | 失败 | 同上 |
| chat_page.dart:550/618/632 「无法获取图片」/语音错误 | 失败 | 同上（语音错误 liveRegion 播报价值最高） |
| chat_page.dart:409（多行长提示） | 引导 | 保持 neutral，观察是否适合迁入 Sheet，不在本方案范围 |
| 其余成功类（复制/导出/接收图片） | 成功 | 换 `tone: success`，行为零变化 |
| chat_controller 请求失败（写进消息流的错误卡） | 消息流 | **不动**。胶囊承担「瞬时提示」，消息流错误卡承担「留档」，双通道并存 |

接线统一走 `humanizeError(raw).summary` 取人话文案、原始串进 `rawDetail` 供复制——不新增文案映射。

## 六、测试计划（`test/floating_toast_test.dart`，仿 immersive_components_test.dart 风格）

1. **存量回归**：`show(context, 'x')` 渲染无图标、无 chip；`pump(3s)` 后 OverlayEntry 已移除（现状行为锁定）。
2. **error 常驻**：`error(...)` 后 `pump(5s)` 仍在；图标为 `error_outline_rounded`、着色 `AppTheme.danger`；仅存在 × 与复制 chip。
3. **关闭路径**：tap × → entry 移除；tap chip → `onPressed` 触发且默认关闭；`dismissOnTap: false` 的 chip 不关闭。
4. **点胶囊降级**：persistent 时 tap 胶囊空白区**不**关闭。
5. **替换策略**：连续 `show` 两次 → overlay 中仅 1 个 entry，且参数为新的一组。
6. **tone 映射表**：4 个 tone → icon/颜色断言（防手滑改枚举）。
7. **Semantics**：error 胶囊带 `liveRegion`；× 有 tooltip/label。
8. **GlassChip 单测**：明暗主题填充/描边色、最小高度约束。

## 八、风险与开放问题

1. **错误被新 toast 顶掉**：替换策略下，错误胶囊可能被后续成功提示覆盖。现状 Toast 频率低（≤3s 一条），先接受；若实测出现互顶，加「danger 期间暂停 neutral 入队」的优先级规则（预留：`_current` 增加 tone 判断即可，~10 行）。
2. **大字号溢出**：`Wrap` + maxLines 3 已兜底常规档；textScale >2.0 的极端档可能出现 chip 换行撑高——胶囊为悬浮层，撑高不挤压内容流，接受。
3. **「反馈问题」接什么**：候选 ① 跳审计日志页导出（audit_log_page 已有复制能力）② `share_plus` 反馈邮件/Issue 模板。P1 开工前定。
4. **双通道心智**：胶囊（瞬时）与消息流错误卡（留档）并存，同一错误可能出现两次感知。缓解：胶囊文案用 `humanizeError().summary`，错误卡保持现有 `formatErrorForMessage` 带技术细节的形态，职责 visibly 不同。
5. **Impeller/Skia 差异**：BackdropFilter 在两引擎均原生支持，无平台分支；低端 Android 机 `disableAnimations` 路径已覆盖。
