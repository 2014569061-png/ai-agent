## 2. P0-1：把回退入口接到"当前任务"

**问题**：[project_change_set_page.dart:43](../../lib/presentation/projects/project_change_set_page.dart#L43) 硬编码 `limit: 1`。用户视角是"我在看任务 A 的改动，点回退却动了任务 B"。

**改法**（这是接线，不是重写）：
1. `ProjectChangeSetPage` 增加必填 `taskId`，由调用方传入当前任务。
2. `_load` 用该 taskId 调 `ChangeSetService.loadOrCapture`（已有接口，签名不变）。
3. 保留"最近任务"作为**入口默认值**，但进入后明确显示任务标题，让用户知道回退的是谁。
4. 调用点共 1 处：[project_home_page.dart:417](../../lib/presentation/projects/project_home_page.dart#L417)。建议同时在 [task_details_page.dart](../../lib/presentation/tasks/task_details_page.dart) 增加入口，让"看改动"和"回退改动"在同一个任务上下文里。

**验收**：
- 在任务 A 详情点回退，只影响 A 的文件，B 不受影响。
- 页面标题/副标题显示当前任务标识与创建时间。
- 回退后仍逐文件报告冲突原因（现有行为不回退）。
- 存量 v1 change set 仍走 `load` 返回 null → 重采路径，不崩。

**为什么排第一**：你的 `rollback` 已经做了"拒绝静默覆盖人工修改"（[:387](../../lib/application/change_set_service.dart#L387)），这是整条链路里最难的部分。**引擎已经对了，只差一个参数**，投入最小、风险最低、直接消除一个真实误操作。

## 3. P0-2：任务内"对话 / 文件 / 结果"三面导航

**DSH 实证**：右栏 tab 类型两阶段注册（先 `sidebarRightTabs.register({id, kind, patterns, priority})` 声明类型，再 `slots.register` 到 `sidebar.right.pane.tab` 座位），布局是**每 Session 一份 SurfaceState** 存 localStorage `dsh.sidebar-right.v1.<sessionId>`，含选中/分栏比例/计数。关键语义：**关闭侧栏与切换会话都保留 tab 记录，只有记录被移除或插件卸载才 abort**；导航参数、资源内容、实时连接**明确不算布局状态**。

**NEXUS 现状**：[`app_shell.dart`](../../lib/presentation/navigation/app_shell.dart#L5) 首页即对话页，无底部导航；任务/项目/工作台从头像菜单分别进入（[chat_page.dart:1683](../../lib/presentation/chat/chat_page.dart#L1683)）。任务详情页内容已经很全（[task_details_page.dart](../../lib/presentation/tasks/task_details_page.dart) 有流水线、Diff、审计、变更审阅），**问题是入口深**。

**改法**：
1. 在会话内加一条**分段控件**（对话 / 文件 / 结果），不要加全应用底部导航。
2. "结果"面复用已有 `TaskDetailsPage` 的展示组件，不新写一套。
3. **布局状态按会话持久化**——直接对应 DSH 的"每 Session 一份 SurfaceState"。你已有 `draft_service.dart` 和会话切换逻辑（[chat_controller.dart:2664](../../lib/application/chat_controller.dart#L2664)），扩展它记录"当前选中的面 + 选中文件 + 滚动位置"。
4. 借鉴那条边界：**导航参数与内容不算布局状态**。只持久化"用户选了什么"，不持久化数据本身。

**验收**：
- 从当前对话最多 2 次操作看到本任务的改动与验证结果。
- 切到文件/结果再切回，草稿、选中文件、滚动位置保留。
- 查看另一会话不取消原运行；返回后状态正确。
- 多项目之间文件/日志/产物不串任务。

## 4. P0-3：作业聚合面（把已有能力提到任务态）

**DSH 实证**（最值得抄的设计）：单一 roster（`job.list`），**没有第二份花名册**。两条独立订阅时机——roster 跟随挂载（`:330`），**输出观测跟随可见性**（`:363-371`，折叠/卸载/关弹层即关闭）。已结束分区默认折叠的判据是"**还有存活任务**"：`settledExpanded = settledOpen ?? liveRows.length === 0`（`:327`），且**最多同时展开一行**（`:315`）。

**停止的语义（这条最精妙）**：三秒两段确认（`KILL_ARM_MS = 3e3`），而 **kill 不占用模型的通知账本**——`README.md:34` 原文："The kill claims nothing in the model's notice ledger, so the owning agent still receives the standard completion notice — the model is told the user stopped its task rather than left to infer it." 即**用户停止后，模型仍会收到标准完成通知，从而知道是人停的，而不是自己去猜**。

**NEXUS 现状**：作业基础设施完备（[`command_tool.dart`](../../lib/infrastructure/tools/command_tool.dart) 有作业列表/日志/取消/守护进程记录，[`terminal_job_panel.dart`](../../lib/presentation/workspace/terminal_job_panel.dart)），但面板**只在 [terminal_sheet.dart:250](../../lib/presentation/workspace/terminal_sheet.dart#L250) 里出现**——而 `chat_page.dart` 对 job **零引用**。也就是：你在对话里看不到后台在跑什么。

**改法**：
1. 会话头部/输入框上方放一条**常驻状态条**（"正在测试 · 2 个文件已修改"），点开进作业面板。**复用** `TerminalJobPanel`，不重写。
2. 落实两条订阅时机：摘要常驻，**输出流只在展开时订阅**——这是省电的关键，Android 上尤其重要。
3. 已结束作业**默认折叠**，判据用"是否还有存活作业"。
4. **对齐停止语义**：确认用户停止后，让模型收到明确的"用户已停止"信号，而不是让它推断。
5. 折叠默认值同 DSH：**同时只展开一个**。

**验收**：
- 对话中随时可见"有几个作业在跑"，不需要进终端。
- 折叠状态下不产生持续输出订阅（可用日志/能耗验证）。
- 用户停止后，下一轮模型输入里含明确的"用户已停止"信息。
- 已结束作业默认收起，且可单独展开。

## 5. P1：详细度分级（一张策略表解决"过程太吵"）

**DSH 实证**：4 档持久化枚举 `ui-chat.transcriptView`（compact/standard/detailed/verbose），由 **POLICIES 表**映射为 4 个字段（`foldCompletedTurns` / `stepGrouping` / `liveProcessDetail` / `settledReasoningPreview`）。原文注释（`:12095-12099`）："Renderers and seats select single fields of this policy; **none of them compares the mode enum**, so adding a mode changes only the table below."

**这条值得学的是解耦方式**：渲染处读**字段**，从不比较枚举本身。加一档只改表。

**NEXUS 现状**：过程展示策略分散在多处，没有单一事实源。

**改法**：
1. 定义 NEXUS 版详细度枚举 + 一张策略表，字段按手机场景裁剪（建议 3 档：简洁/标准/详细）。
2. **改造调用点：读字段，不比较枚举**。这是本次最可迁移的软件设计经验。
3. 默认档位按设备能力选（DSH 桌面取 standard、Web 取 detailed，这就是"按环境选默认"的实证）。

**验收**：新增一档只改策略表，UI 代码零改动（可用测试锁定：枚举→策略表映射测试）。

## 6. P1：技能系统的契约对齐

**DSH 实证（已逐条实测复核）**：
- **发现只有一层**：`<root>/<name>/SKILL.md` 或 `<root>/<name>.md`；判定是 `segments.length === 2 && segments[1] === "SKILL.md"`，即**嵌套 `**/SKILL.md` 故意不发现**。
- **6 级 rank**（实测常量）：100 `.dsh/skills` → 200 `.agents/skills` → 300 customSkillDirs → 400 `<dshHome>/skills` → 500 `<agentsHome>/skills` → 600 bundled。
- **frontmatter 严格**：`name`/`description` 必填，name 须匹配 `/^[a-z0-9]+(?:-[a-z0-9]+)*$/`；布尔字段严格语法，**非法拼写会连整个 skill 一起丢弃**；三个驼峰旧键一律抛错。
- **注入方式**：走 `agent/pre-step` waterfall，以 `<system-reminder><available_skills>` 的 durable 用户消息发布；按条目 digest 判重发；**描述默认截断 500 字符**。

**NEXUS 现状**：已有 skill 体系（`skill_parser`/`skill_store`/`skill_installer`/`builtin_skills`，[assets/skills/](../../assets/skills/) 下 9 个 SKILL.md）。

**改法**：
1. 对齐 name 正则与必填校验；**采用"非法即整体丢弃"策略**（比"部分容错"更可预测，也更容易定位问题）。
2. 明确 rank 顺序（项目 > 用户 > 内置），同名时按 rank 决定。
3. **描述截断**：注入 prompt 时截断，避免长描述吃 token——这与你的上下文预算体系（[prompt_budget.dart](../../lib/application/prompt_budget.dart)）天然契合。
4. 判定规则要写进文档：嵌套不发现，是**有意为之**还是 bug，需明确取舍。

**验收**：给定一组非法 frontmatter 用例，行为与文档一致；同名 skill 按 rank 唯一解析；注入体积有上限。

## 7. P1：审批的 fail-closed 不变量

**DSH 实证**：三段式——`tools/pre-execute` waterfall 返回 allow/deny/ask/cancel → **单调 guard**（只能否决，不能翻案）→ `ask` 走 approval 服务。关键：approval **未挂载 / 无 agent / rejected / cancelled / unavailable 五种情况里只有 allowed-once 放行**。deny 的模型可见文本统一是 `Error: <reason>`。

**NEXUS 现状**：[`approval_policy.dart`](../../lib/application/approval_policy.dart#L10) 已有 `decide({mode, risk, trusted, sensitive})`，**语义清晰且注释解释了取舍**（危险级任何模式都逐次确认；敏感把 safe 抬到确认级但不覆盖 fullAccess——这条判断是对的）。[`tool_registry.dart:108`](../../lib/infrastructure/tools/tool_registry.dart#L108) 已有 `ToolApprovalGate` 接口。

**值得补的只有两点**：
1. **fail-closed 不变量**：任何"不确定/异常/服务不可用"路径都应落到**拒绝**，而不是放行。请专门写测试锁死。
2. **单调否决**：确认 NEXUS 是否存在"后置环节能否决但不能翻案"的结构；如果没有，值得引入，它能让安全策略可组合。

**验收**：approval 服务抛异常/返回未知态时，工具调用被拒绝且有明确原因；有测试覆盖这 5 类失败路径。

## 8. P2：预设从"文件目录"到"声明组合"

**DSH 实证**：`agent.cordis.yml`/`preset.yml` 已**废弃**——`editing-cordis-compositions/SKILL.md:70` 原文 "Nothing reads that directory any more"。现行是 `@deepseek-ai/dsh-agent-preset` 行的 config `{ id, plugins(必填), name?, description?, order? }`，id 规则小写字母/数字/连字符。随包 preset 在 `dsh-web-app/presets/{standard,ptc,minimal,cordis}.patch.yml`。

**NEXUS 现状**：[`plugin_store.dart`](../../lib/infrastructure/plugins/plugin_store.dart#L16) 的包格式是 `{name, version, kind, tools, agents}`，kind ∈ tool/agent/bundle，V1 **明确不支持任意本地代码**（安全边界，且有 `_maxToolsPerPlugin = 20` 与 DNS 二次检查）。

**判断**：**NEXUS 的边界选择是对的，不要为了"像 DSH"而放开**。Flutter 无法也不应加载 TypeScript/Cordis 插件。可借鉴的只有"**preset 是一份可预览的声明式组合**"这一点，而这你已经有了。

**建议动作（低优先级）**：
1. 把"工具范围 + 技能 + MCP 引用 + 验证规则"组成一个可预览的配置包。
2. 导入时做依赖检查与缺失提示（缺模型/MCP 要显式告知）。
3. 保持"只引用凭据、不内嵌密钥"。
