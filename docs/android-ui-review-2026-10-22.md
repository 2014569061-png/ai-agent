# Android 全页面 UI 优化建议

审查日期：2026-10-22。范围：当前 Android 手机端；保留蓝白、柔光、圆角风格和左侧抽屉导航。本次只审查和写建议，未修改应用 UI。

## 审查依据与边界

- 检查 57 个 Android 页面源文件，以及 `RunDetailPage` 这一额外详情入口，共 58 个页面入口；同时检查导航、主题、公共组件与主要弹层。
- 重新生成 411dp 普通字体、360dp / 1.6 倍字体共 116 张测试渲染图；页面清单、渲染和重试测试共 118 项通过。通过测试只说明相应布局没有抛出异常，不代表视觉质量已经达标。
- 启动已有 `Nexus_Preview_API_36`，预览达到 `[preview] Ready`，核对实际首页、侧栏、我的与设备能力页。未逐一在模拟器操作所有页面的所有状态。
- 测试渲染以空数据和固定样例为主。原生接口未注入导致的 `MissingPluginException`、测试项目缺少网页入口、Git 样例错误等，不作为真实设备的功能故障。下文对这些状态的建议关注错误呈现与恢复入口。
- 测试字体造成的首页快捷建议方框不作为手机字体缺陷。模拟器首页中文显示正常。
- 聊天流式输出、真实工具执行、审批、键盘、导入恢复等复杂状态，本次结合组件代码提出建议，没有为审查而发起收费模型请求或执行危险操作。

**主要判断：配色已经形成共同方向，但信息取舍、页面密度、排版与组件使用还没有形成同样稳定的规则。下一轮最有价值的工作是减少无效占位、重复入口、常驻说明与并列强调。**

## 最先解决的共性问题

| 问题 | 当前可见例子 | 建议 |
| --- | --- | --- |
| 首屏主次不清 | 服务商页先展示多组添加方式；Agent 编辑页很早进入多组参数滑杆；项目页展示环境、标签和多组工具 | 首屏先回答“当前是什么、下一步做什么”；每页保留一个明确主操作，高级项逐步展开 |
| 说明文字挤占内容 | 成果中心、费用账本、远程连接、默认助手、备份页均有较长常驻说明 | 一句摘要加“了解详情”；授权范围、费用含义、覆盖后果仍放在相关操作前，不能隐藏必要信息 |
| 空状态布局不一致 | 有的空状态靠近页面中部，有的被 `Expanded` 的剩余空间推到很下方 | 在内容区域靠上居中，位置随键盘和字体调整；图标、标题、说明、可选操作遵循一套间距 |
| 标题体系不够克制 | 一级页 30sp 大标题、普通页 21sp 标题、较重的 12sp 副标题同时出现；部分标题过长 | 一级标题建议 26–28sp；二级 20–22sp；副标题 12–13sp 常规字重，仅在补充必要信息时出现 |
| 文本被截断后不可理解 | 工具权限说明、MCP 页副标题、日志与能力错误信息中存在较长省略文本 | 列表只写短摘要，完整说明在明确的展开入口中；授权与危险后果不能靠省略号承载 |
| 过多表面和圆角层级 | 卡片中嵌字段，再嵌小统计卡、状态胶囊和按钮 | 普通列表按组使用一个表面；同一信息层级不再包多层卡片；正文、代码、日志可直接排版 |
| 颜色与徽标密度偏高 | 项目环境的一排红色缺失标记；设备页英语状态牌；分析页多色统计模块 | 蓝色集中用于选中与主操作，状态颜色只表达实际语义；默认展示一个聚合状态，展开看具体能力 |
| 工具栏操作太多 | 日志页多个图标并排；成果页多个相近的小图标；部分详情页导出、复制入口密集 | 高频且明确的操作最多保留两个，其余进入有文字的“更多”；复制、刷新优先下拉或菜单 |
| 搜索与筛选形式不统一 | 胶囊搜索、18dp 搜索、窄搜索、下拉选择、多个状态胶囊混用 | 搜索统一组件；两三个视图用分段选择；大量筛选用“筛选”面板，选中条件以摘要表达 |
| 技术命名直接成为主文案 | Provider、Run、SLO、PRIVILEGE CH.、success、unknown 等 | 主层用可读中文，如“服务商”“运行详情”“缺少数据”；技术 ID 与原始状态进入详情，协议名和模型 ID 保留原值 |
| 底部动作缺乏稳定模式 | 新建悬浮按钮、双固定按钮、正文中的按钮、空态按钮并存 | 内容列表用一个新建入口；表单用稳定的保存区；危险操作与普通按钮分离；避免同一操作重复抢占注意 |
| 全局背景与局部留白失衡 | 普通列表也有较明显蓝底；首页图形到欢迎语、建议到输入区的空白跨度大 | 首页保留局部柔光，普通页降到接近实色的浅冷灰；用内容分组与节奏建立层级，不用持续装饰补空白 |

以下尺寸为下一轮的设计建议，不表示要推翻现有规范：页面侧边距继续 20dp；分组间距 24dp；卡内留白 16dp；普通列表行自然增高，基础约 56–64dp；控件触摸范围不小于 48dp。表面圆角建议集中为 20–24dp，输入框 18dp，聊天输入区 26dp，面板 28dp。不同页面明确需要较紧凑的代码或日志密度时允许例外。

## 导航与助手协作

| 页面 / 区域 | 具体问题或重点 | 建议后的首屏与操作 | 默认收起 |
| --- | --- | --- | --- |
| 统一侧栏 | “新建对话”和已选助手都是较大的浅蓝块；四个主入口与工具占据前半屏，最近会话偏下 | 缩小品牌区；新建对话使用较轻的独立操作行；助手、任务、工作区用紧凑列表；“我的”可固定在底部。让最近会话更早出现；保留全部入口 | 助手与工具、历史会话的管理动作；搜索可按需展开，不能删掉搜索能力 |
| 助手首页 `chat/chat_page.dart` | 视觉比其他页轻，但图形、欢迎语、建议、输入框之间的留白缺少连续节奏；长模型 ID 抢占输入区 | 欢迎图形建议缩到 64–72dp，缩短其与欢迎语的距离；保持一句欢迎语与最多三个建议。建议优先“整理资料、分析项目、继续任务”等与当前真实状态匹配的动作；创建 Agent 保留在身份选择与管理入口。模型胶囊限宽，完整 ID 在选择面板查看 | 执行配置、费用、Token、环境检查；未配置模型时只保留一处明确引导 |
| 进行中的对话（同一页面不同状态） | 工具、计划、回答、运行状态容易竞争；组件统一颜色后仍需明确阅读顺序 | 用户浅蓝气泡；助手正文直接阅读。执行区只显示“正在做什么 / 已完成什么 / 是否需处理”，长过程可展开。输入区随空闲、执行、暂停切换主动作，避免同时出现多个相似控制 | 详细思考、工具参数、原始日志、Token 与耗时；计划确认和审批不可藏进普通日志 |
| 历史会话 `history/history_page.dart` | 搜索正文、搜索标题、全量搜索的边界靠副标题解释；筛选样式与其他列表不同 | 明确“搜索本页会话”；跨类型查询继续使用全量搜索入口。时间分组、会话标题、一行摘要、更新时间即可；收藏、置顶和重命名放条目更多 | 消息匹配片段超出一行的部分、批量管理 |
| 全量搜索 `search/global_search_page.dart` | 搜索、类型下拉、日期筛选形成多层顶部区域；结果中原始 ID、完整路径和英文状态较抢眼 | 首屏一个搜索框加筛选按钮；类型可以短标签切换。结果显示标题、类型、匹配片段与可读时间；原始 ID 不作标题，标题缺失时给明确的“未命名任务”等回退文案 | 完整路径、内部 ID、复杂日期与项目条件 |
| 任务 `jobs/jobs_inbox_page.dart` | 待处理、近期任务、收件箱已有清晰语义，但空态位置很低；顶部刷新/搜索可进一步收敛 | 待处理优先，任务行按“任务名—状态—下一步”组织；待审批项直接提示需确认的动作；空态靠上。保留未读与待处理的区别 | 完整执行过程、已读记录、次级时间 |
| 开发任务中心 `tasks/development_tasks_page.dart` | 多个状态胶囊一开始就展示一排零计数；与通用任务页定位容易重叠 | 定位为开发任务历史与筛选，不再做第二个总收件箱；显示全部与有内容的常用状态，其余在筛选面板；空态说明从哪里产生任务 | 原始工作区路径、模型参数、零计数筛选 |
| 开发任务详情 `tasks/task_details_page.dart` | 类型、状态、总览、小卡与流水线多层重复；无输入也占一块；底部部分禁用动作占空间 | 先放结果摘要、当前状态、需用户处理的动作与成果；之后是改动和验证。无指令时用一行而非空白卡；只呈现当前可用的主操作，并解释重要的禁用原因 | 已完成的完整流水线、原始报告、审计 JSON；回滚进入独立确认流程 |
| 定时任务 `scheduled/scheduled_tasks_page.dart` | 主动提醒和 Agent 定时执行同时出现，权限说明较长；多个创建入口可能分散理解 | 清楚分开“提醒”和“Agent 定时任务”；列表显示下次执行时间、开关、上次结果；新建入口先选择类型。当前权限不足时仅就受影响的能力给出具体提示 | 已结束记录、调度解释；创建与启用时保留费用和权限说明 |
| 可复用工作流 `workflows/mobile_workflows_page.dart` | 参数框、完整模板步骤、两种执行按钮同时平铺 | 先选择模板并展示一句用途，再填写本次参数；“试跑”与“实际执行”的差异紧邻按钮写清。步骤默认显示数量与概览，展开核对；实际执行仍保留预览确认 | 每步技术类型、详细配置和历史日志 |

| 浏览器 `browser/browser_page.dart` | 地址、手动控制说明、两种接管按钮、无障碍提示、错误信息都占网页上方 | 顶部地址栏加一个明确控制权状态；相关权限提示只在启用对应能力时出现。人工接管必须始终易找到；异常用可恢复的小区域，网页区域成为主体 | 能力说明与诊断；外发数据、授权范围和助手实际控制状态不能隐藏 |

| 计划确认 | 首先列目标、拟执行步骤与影响对象；确认和修改计划清楚区分；完整推理与参数可折叠，用户需要确认的执行范围不能折叠到不可发现 |
| 工具审批 | 保留已有渐进展开参数的方向。首屏用“动作—对象—影响—决策”，命令可复制；本次/本会话/永久授权的视觉层级和实际范围必须匹配，不能把长期授权做成普通的蓝色主按钮 |
| 设备动作预览与恢复确认 | 按对象分组列出具体变化、不可逆项和将交给哪个系统能力；多项结果分开呈现，失败项可查看原因；不要用整面红色制造噪声，也不能弱化实际覆盖/删除后果 |
| 语音输入 | 明确未开始、正在听、识别中、可编辑、已停止五种状态；转写正文占主体；语言设置次级；自动发送是清楚的显式选项。不要做成通话 UI |
| 分享与页面文字核对 | 来源与有效性一行摘要，编辑区为主体；“加入草稿”是主操作，丢弃次级。到期时说明需重新读取，不能默默保留可误用的确认按钮 |
| 提示词 / 记忆 / 上下文编辑 | 短表单用底部面板，长正文使用足够大的编辑区；标题、必填、保存位置一致；键盘不遮盖主按钮；存在修改时返回确认 |
| 服务商 / MCP 添加 | 基础字段随协议切换，高级参数折叠；敏感值默认遮挡但可按需查看；校验错误定位到字段；失败不清空已填写内容 |
| 导入 / 导出 / 密码 | 预览范围、目的地与覆盖后果先于最终确认；密码错误就地提示；展示已有的真实导入导出能力，不加入不存在的账号或云同步 |
| 环境检测 / 安装 | 当前目标、需要的依赖、进度与下一步分层；完整下载/安装日志可展开；断线、失败、取消都给出真实可用的继续方式 |
| 文件树 / 文件预览 | 路径面包屑与当前目录清楚；文件名优先，路径可展开/复制；减少每项大图标背景；长文件名不靠强行缩小字体塞下 |
| 终端面板 | 与独立终端保持同样的连接状态、辅助键和复制规则；面板高度能容纳键盘；拖拽关闭不能误丢仍运行的会话 |
| 会话分支 / 运行预设 / 协作计划 | 用列表与小型步骤概览；当前选中和切换影响明确；原始配置默认折叠。只呈现实际存在且可执行的预设和协作入口 |
| 用量与上下文面板 | 保留输入区更多入口，避免恢复常驻指标栏；先放摘要，再解释预估、未知与结算差异；数字采用稳定对齐和明确单位 |
| 更新 / 安装任务 | 当前版本、目标版本、状态与一个主操作；发布说明折叠；安装权限和来源在需要时清晰告知，不引入营销卡 |

## 状态与交互的统一要求

1. **加载**：仅替换尚未完成的区域；已有列表刷新时不整页消失。骨架尺寸接近最终内容，避免加载前后大幅跳动。
2. **空数据**：图标建议 40–48dp，标题 16–18sp，说明尽量两行以内，一个可选主操作；避免大型图形加大量空白。没有明确下一步的页面不硬加按钮。
3. **失败**：一句可读原因、下一步、明确重试；原始异常进入诊断。局部失败不把整个页面变成失败页。
4. **禁用**：视觉上与可点操作区分；用户需要理解的原因在旁边，例如“填写地址和令牌后可连接”，不只呈现灰色按钮。
5. **选中**：单一浅蓝底加文字/勾选即可，减少同时出现边框、阴影、圆点、填充图标。
6. **运行**：给当前动作，不同时堆多个转圈；进度没有真实分母时不画虚假百分比。暂停、继续、停止根据真实状态出现。
7. **完成 / 部分完成 / 待核实**：分别表达，不把文件存在、保存副本、命令退出和任务成功混为一谈；结果要能继续预览或导出。
8. **键盘**：输入框、最近消息、正在编辑字段和主操作可见；侧栏打开先收键盘；关闭键盘不丢草稿。
9. **返回与手势**：先关闭浮层，再返回详情；未保存编辑必须受保护。终端、代码和网页的横向交互要与抽屉边缘手势协调。
10. **大字体**：文字自然增高，说明不缩成细小字；重要提示不因字体放大而消失；表单标签、状态和操作允许换行。
11. **无障碍**：图标有明确语义；状态不用颜色单独表达；屏幕阅读器按标题、内容、操作顺序读取；装饰图形不重复播报。
12. **动效**：约 180–260ms 的轻量过渡；长列表、日志和输入不使用装饰性循环；尊重系统减少动态效果。

## 建议的改进顺序与验收

**第一批：高频体验。** 公共页头与文字层级、侧栏、助手首页/会话/输入区、任务、工作区、我的。先解决看得最多的密度、留白、重复入口和状态问题。

**第二批：长表单和长说明。** Agent、服务商、MCP、工具权限、知识库、记忆、项目主页、设备能力。用基本/高级结构和局部帮助减少首屏负担。

**第三批：结果和恢复。** 成果、交付、费用、备份、运行详情、诊断、错误状态。重点让用户理解结果可信度、覆盖范围和下一步，而不是仅换颜色。

验收应同时包含：普通手机与窄屏大字体；空/有数据/长名称；加载/局部失败；键盘；运行/审批/暂停/完成；返回与未保存。每批在模拟器看真实交互，再用隔离测试补布局与状态。x86 模拟器不能替代 ARM64 内置运行时的真机验证。

**完成标准：打开任何一页，用户能快速找到当前内容、一个主要动作和必要状态；其他信息有明确入口，但不抢占首屏。**
