# NEXUS 桌面对话区紧凑布局

日期：2026-10-16

## 反馈与调整

针对“组件留白太大，输入框占据太多空间，导致对话页面很小”：

- 仅对嵌入桌面工作台的对话页，将正文与输入区共同宽度上限从 700px 放宽到 1120px；窗口不足时使用实际可用宽度。移动端/独立聊天页保持原上限。
- 桌面输入框从最少两行改为单行起步；随内容增长，通常最多显示五行，较矮聊天区最多三行，更多内容在框内滚动。
- 输入容器上下内边距、发送按钮外层占位收紧；实际发送按钮保留原尺寸、焦点与语义标签。
- Code/Plan 切换并入同一输入工具栏，运行中仍禁止切换。计划模式确认提示保留。
- 去掉常驻的底部快捷键说明行；快捷键提示移到“更多输入工具”的 tooltip 和菜单中。
- 原“会话设置”操作移入更多菜单；附件、模型、审批策略、代码块、发送、暂停、继续与停止操作保留。
- 桌面执行面板占位上限从可用高度的 38%/320px，改为 25%/180px，超出的计划/步骤仍可滚动查看；移动端不变。
- 桌面主题启用紧凑控件密度，去除移动端触控用的额外占位；通用表单输入内边距由水平12/垂直10调整为水平10/垂直7。不固定输入高度、不缩小正文字号、不限制用户文字缩放。

## 对比说明

1440×900、同一测试会话、相同文字与窗口：输入框表面高度从约 107px 降至约 67px。结合模式行与快捷键说明合并，底部常驻区域约少占 100px；这些空间归还消息列表。

上述为隔离渲染夹具截图测量，实际高度随系统字体、文字缩放、输入行数、运行状态而变化。只有两条测试消息时，消息列表内部自然仍有空白；本轮缩减的是控件占位，而不是人为填满消息区域。

## 验证内容

新增 `test/desktop_compact_layout_test.dart`，8 项针对性测试：

1. 空输入区高度上限、长文本按需增长及清空后回缩。
2. Enter 发送、Shift+Enter 换行、中文输入法组合态不误发送。
3. 仅附件发送。
4. 运行中的暂停、继续与显式停止。
5. 内联模式切换、计划警示、运行锁定及会话设置菜单。
6. 480px 宽/2×文字/短窗口的多行输入。
7. 桌面通用输入框紧凑尺寸与移动端原 48×48 操作槽。
8. 真实 DesktopShell 的宽高分配：1440×900、900×640、1280×720/1.5×文字；在 1440×900 下输入表面宽度超过1000px、空输入高度≤84px、消息视口高度超过580px。

最终验证结果：
- `flutter analyze --no-pub lib/presentation test/desktop_compact_layout_test.dart`：No issues found，退出码0。
- 34个相关测试文件联合回归：**231项全部通过，退出码0**。包含桌面工作台、深层页面、输入状态矩阵、流式重建、键盘避让、移动端触控、会话指标与截图回归。
- 已人工查看1440×900浅色对话与1280×800深色对话截图，未见明显控件溢出。

最终联合分析与回归结果记录于：

## 边界

本轮未构建 Windows 可执行程序，未执行真实模型/MCP/设备操作，未修改数据库、模型协议、审批策略或自动授权逻辑。没有把全部测试仓库作为本轮验证范围。
