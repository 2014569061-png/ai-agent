## 1. 决策摘要与范围约束

产品目标：让 NEXUS 成为用户日常首选的手机 AI 助手，同时完整保留并升级 Agent 任务工作台、项目开发和自动化能力。

用户已明确：本次包含最初提出的所有移动端升级，以及后续提出的个人助手替代方向。以下各工作包均属于总交付范围；实施先后不表示取消、降级为可选或留待另一个不确定版本。不能把个人助手首页完成，等同于整个大版本完成。

v1.2 将实时多模态、具体应用连接、关联上下文、可复用工作流、研究成果、可操作结果、执行中纠正和快速接入加入总范围。F15–F22 深化 F01–F14，复用原有运行、授权和数据基础；不能另建互不兼容的执行系统。托管服务是否实际运营属于有成本的单独决策，快速接入功能本身必须交付，具体边界见 F22。

三条完整使用链路：

1. 日常助手：随手唤起 → 文字/语音/分享输入 → 理解需求 → 获取授权 → 手机动作或内容处理 → 明确结果。
2. Agent 工作：发起目标 → 计划与预算 → 执行与审批 → 中断恢复 → 成果验证 → 使用、分享和继续修改。
3. 项目创作：创建/导入项目 → 配置目标环境 → 编辑与执行 → 预览与测试 → 检查变更 → 导出或交付。

交付原则：

- 全面改造 Android 实际页面、公共组件、导航和业务链路；不以修改桌面分支代替手机适配。
- 复用现有可用服务，不推倒重写整个 Flutter/Riverpod/Drift 架构。
- 原有高级功能保留可达入口；首页简化不得导致能力消失。
- 先验证系统限制，再锁定实现方式；技术不可行项必须记录证据、替代方案与用户决策，不得默默标记完成。
- 本文给出所有功能的实施范围，但不承诺第三方应用、厂商系统和模型服务商提供其并未开放的能力。
- “替代助手”以实测任务覆盖率衡量，不宣称获得系统预装应用的全部权限。

语音识别和默认语音助手接入：本轮针对 `SpeechRecognizer`、`VoiceInteractionService` 等标识的检索未发现实现；暂按新增工作估算，技术阶段需进一步确认依赖及原生桥接。

已有审查记录必须复核，不能直接当作当前仍未修复的问题：

- 删除最后一个服务商后的遗留凭证处理。

- 定时任务真实结果与成功状态一致性。
- 预览端口与启动命令一致性。
- 分层守护测试；共享代码修改涉及 Windows 时还须检查其备份调度。

## 3. 用户、场景与成功定义

同时服务两类使用深度：日常助手用户与创作者/开发者。采用同一本地用户资料和数据体系，通过入口和渐进展开适应复杂度，不维护两套互相割裂的产品。核心本地功能不要求登录；跨设备配对身份在 F13 定义，不假定已有统一账户服务。

| 场景 | 示例 | 成功证据 |
| --- | --- | --- |
| 即时问答 | “解释一下这个概念” | 回答可追问，联网内容附来源 |
| 图片理解 | “这张截图里的报错怎么处理” | 明确读取所选图片，结果能关联原图 |
| 资料整理 | 分享文章并要求提炼重点 | 摘要、来源、导出或收藏入口 |
| 个性记忆 | “记住我喜欢简短回答” | 可查询、修改、删除的记忆记录 |
| 提醒待办 | “明天下午三点提醒我交材料” | 具体日期时间、持久化提醒、通知回查 |
| 手机动作 | 打开指定应用或准备分享内容 | 动作真实执行；只完成跳转时明确说明 |
| 项目创作 | 创建静态网页 | 生成文件、可用预览、验证结果 |
| 编程修改 | 修改脚本并运行检查 | 变更记录、执行输出、可恢复点 |
| 长任务 | 离开应用后继续处理 | 状态可信、恢复或中断说明、完成通知 |
| 订阅自动化 | 定期检查用户指定事项 | 真实运行结果，只有符合条件才提醒 |
| 远程接力 | 手机发起远程构建 | 执行端、连接状态、产物与日志可追溯 |

北极星指标：每周用户确认有帮助、或实际使用了成果的成功任务数。辅助指标包括首次任务完成率、重复使用率、任务成功率、手动接管次数、恢复成功率及每个成功任务成本。仅生成回复或消耗 Token 不算成功。

## 4. 信息架构与导航

默认一级导航：**助手 / 任务 / 工作区 / 我的**。

采用四入口是为了同时落实日常助手与最初的完整项目工作台要求。专业功能渐进展示，但工作区保持一级可达；不采用会把完整工作台埋入设置的三入口方案。

| 一级入口 | 二级结构 |
| --- | --- |
| 助手 | 新对话、实时会话、语音、拍照/附件、分享处理、最近会话、完整历史搜索 |
| 任务 | 待处理、进行中、已完成、提醒、定时与自动化、工作流 |
| 工作区 | 项目、成果、资料、研究；项目内含会话、文件、预览、变更、终端 |
| 我的 | 模型、连接的应用、Agent 与扩展、个人记忆、权限与设备、数据、外观、用量、诊断 |

全局要求：

- 待审批/失败/需要补充信息有角标；正在运行的任务有轻量返回入口。
- 各导航保留页面状态、输入草稿和滚动位置；通知与深链落到具体任务。
- 返回顺序：先关闭键盘/最上层弹层，再退出子页；未保存编辑有离开处理。
- 系统入口发起内容时明确“新任务”或“加入当前任务”，不误发到其他会话。
- 全局搜索覆盖完整历史、项目、任务和成果；不同类型分组，结果可追溯。
- 当前最近 30 条会话的本地标题过滤不冒充全量搜索。
- 常用专业入口支持固定；普通用户不需要理解 MCP、PRoot 或 Token 才能完成首个任务。
- 离线时仍可查看历史与成果、编辑草稿、管理本地资料和待办；需要联网的请求显示未提交或等待网络。恢复网络不能自动重放未经确认的外部动作。端侧推理/离线 ASR 另行探测，未安装模型或识别服务时不宣称可用。

## 6. 功能规格与验收

### F01 首次体验与模型接入

- 选择用途后准备初始模板；配置模型或查看明确标识的演示，不伪装真实执行。
- 检测认证、端点、模型、工具/图片能力；支持手动覆盖能力声明并显示检测时间。
- 将网络、认证、额度、模型不支持分别提示；保留用户已填写内容。
- 适用时提供本地模型连接，但不暗示手机可直接访问其他设备的 localhost。
- 验收：有效配置用户能在三分钟目标内完成示例任务；配置与推理耗时分别记录。

### F02 语音助手

- 按住说话、点击录音、可编辑转写、发送前取消；提供可选择的自动发送设置。
- 状态：空闲、录音、转写、待发送、思考、播报、错误。录音开始/结束有明确反馈。
- 支持点击中断 TTS；用户开启下一轮录音时停止播报，处理音频焦点、来电和耳机切换。
- 系统 ASR 不可用时提供明确提示及可配置替代服务；语音数据去向在配置中说明。
- 前台连续对话纳入本期，明确会话开启/结束；后台唤醒词单独实现验证，不通过循环调用短句识别伪造。
- Android 官方指出 SpeechRecognizer 不适合持续识别，因此持续会话与唤醒需独立设计。[SpeechRecognizer](https://developer.android.com/reference/android/speech/SpeechRecognizer)
- 验收：中文普通话、数字/日期/应用名、噪声、拒绝权限、无识别服务、网络失败、来电中断均有记录；录音退出后释放麦克风。

### F03 系统助手入口与上下文

- 保留并升级桌面快捷方式、小组件、分享与深链；新增默认助手接入适配及用户引导。
- 技术验证 `VoiceInteractionService`/会话服务、助手角色选择、系统手势调用、冷热启动及锁屏行为。
- Android 对选中的 VoiceInteractionService 有系统管理机制，但不能据此推断所有厂商按键、唤醒词或锁屏动作都可用。[VoiceInteractionService](https://developer.android.com/reference/android/service/voice/VoiceInteractionService)
- 当前页面理解优先接收用户分享/截图；系统提供上下文时标明来源；受保护页面明确无法读取。
- 悬浮入口提供用户主动启用、关闭和权限撤销行为；不默认覆盖其他应用。
- 验收记录每台设备的入口成功率；不支持入口时仍能通过快捷方式/分享完成同一任务。

### F04 手机动作与跨应用执行

- 动作目录按实际支持范围发布：应用启动、标准内容分享、日历/提醒入口、设置跳转、用户授权文件操作等。
- 每个动作定义参数、前置条件、能力探测、授权、风险、执行结果、验证方式、幂等策略和撤销能力。
- 优先使用公开接口、Intent、Deep Link；通过系统页面交给用户提交时，状态为“已准备/等待完成”，不写“已发送/已创建”。
- 需要选择收件人、账户、应用或时间时先消歧；不能由模型猜测关键对象。
- 外部发送、删除、交易等关键动作提供具体预览与确认；授权绑定本次参数，修改参数后重新确认。
- 现有设备自动化的动作白名单与一次性票据流程继续复用，禁止在新入口绕过。
- 建立普通 Android API、特殊权限、Shizuku、Root 四级能力矩阵，分别实测已支持动作。当前 `android_device_tool.dart` 已有 Root/Shizuku 相关通道，必须保留受控专业入口；普通助手核心流程不能以 Root/Shizuku 为必要条件，也不能默认申请这些权限。
- 界面自动化纳入技术验证和受控适配范围，包含目标应用版本识别、步骤验证、超时和用户接管；不承诺任意应用通用成功。
- 若采用 AccessibilityService，分发渠道必须先确认。Google Play 对基于该 API 的自主规划执行有明确限制，通用 AI 代理不能假定可以按此路线发布；需审查确定规则自动化、公开接口或其他合规实现路线。[Google Play AccessibilityService 政策](https://support.google.com/googleplay/android-developer/answer/10964491)
- 验收：执行成功须有设备/接口反馈；无法可靠验证时显示“待核实”，失败不盲目重放有副作用动作。

### F05 对话、上下文与全量搜索

- 聊天支持图片/文件、来源引用、流式输出、停止、继续、分支与草稿恢复。
- 发送前可检查附带文件、知识来源、相关记忆；允许移除不需要的上下文。
- 工具默认显示用户能理解的摘要，展开查看详细参数、日志和耗时。
- 历史、任务、项目、成果走分页数据库搜索；按类型、时间、项目过滤。
- 验收：长会话流式输出时滚动稳定，不强制抢回底部；搜索可找到早于最近 30 条的记录。

### F06 任务工作台与恢复

- 统一排队、运行、待输入、待审批、暂停、成功、失败、取消；结果另存完整/部分及验证状态。
- 区分取消请求已发出与执行端已停止；已发生的外部动作不能声称已撤销。
- 每个任务有目标、步骤、事件、预算、执行端、成果及相关会话。
- 重试创建新 attempt，继承可复用步骤；审批超时、断网、进程回收都有下一步入口。
- 运行检查点包含已完成工具、待处理动作、模型上下文引用和必要恢复元数据；敏感内容按既有脱敏边界处理。
- 验收：切页面、锁屏、断网、进程终止后任务状态一致，无重复发送、重复修改或虚假成功。

### F07 成果中心

- 复用 ProjectArtifact，扩展为可容纳非项目任务的成果索引，兼容既有 projectId 必填数据。
- 支持文本、文件、图片、网页、构建包；展示来源任务、版本、验证情况、大小、路径和创建时间。
- 提供预览、复制、导出、分享、继续修改；失效文件标记缺失并提供恢复线索。
- 内容生成完成、文件存在、可打开、验证通过分别记录。
- 验收：网页任务交付真实可打开预览；导出文件可在应用外打开，变更后生成新版本关联。

### F08 项目开发完整升级

- 项目创建/导入、开发目标识别、文件树、编辑、Git 变更、终端、预览、验证及成果全链路改造。
- 设置明确区分手机本地、Termux/SSH、远程执行端；任务创建前检测目标能力。
- 静态网页不安装无关 SDK；工具链显示大小、磁盘需求、进度、失败原因和继续安装。
- 变更审查包含文件差异、验证结果、恢复入口；不覆盖用户并行修改。
- APK 本地构建保留小型 Java 项目边界；大型/不受支持构建提供远程路线和能力说明。
- 验收：静态网页、脚本修改、简单 APK、远程构建分别形成固定案例；PRoot/APK 在 ARM64 真机验证。

### F09 个人记忆与知识库

- 记忆分偏好、用户主动保存资料、进行中的事项；保存来源、更新时间、有效期/撤销状态。
- 支持“记住”“忘掉”“本次不保存”、编辑纠错、冲突处理及关闭自动建议记忆。
- 敏感信息不默认提取长期保存；删除后清理相关索引，后续检索不再命中。
- 知识库支持导入状态、来源定位、重新处理、删除与失败重试；回答引用真实资料片段。
- 验收：用户能查到助手使用的记忆；删除/更新后下一轮行为正确，跨项目资料隔离符合配置。

### F10 提醒、定时执行与主动服务

- 数据模型区分提醒（通知用户）与定时 Agent 任务（执行工作），以及条件触发设备自动化。
- 自然语言时间解析后显示绝对日期、时区和重复规则；不确定的“下午”等表述需要消歧。
- 支持试运行、暂停、编辑、取消、下次时间、最近结果、延迟原因和失败处理。
- 对错过的提醒/任务定义补发、跳过、合并策略；防止重启后重复通知。
- “准点提醒”和“可延迟后台任务”使用不同调度契约。当前 `DeviceAutomation.kt` 使用非精确闹钟，不能直接承担“15:00 准点提醒”的保证。需要准点的场景评估 AlarmManager 精确闹钟及适用的特殊访问权限，在调度前检测授权；权限不可用时明确提示延迟可能，或提供系统闹钟/日历入口。授权撤销、重启后重建调度均纳入验收。[Android 闹钟调度](https://developer.android.com/develop/background-work/services/alarms)
- 重复提醒明确采用固定所在地时间或跟随设备时区；夏令时缺失/重复时间分别定义跳过、顺延或一次触发策略，防止重复通知。
- 通知按任务聚合，只有完成、失败、需要动作或用户订阅变化时主动打扰。
- 持久后台执行按任务类型选择 Android API，不能承诺永久常驻或全部准点。[Android 后台任务指南](https://developer.android.com/develop/background-work/background-tasks)
- 验收：权限拒绝、时区/系统时间变化、重启、Doze、网络恢复、审批过期均可解释且可回查。

### F11 Agent、技能、MCP 与模板

- 统一能力发现入口，区分角色模板、技能指令、外部工具服务和提示词。
- 每项显示用途、示例、工具范围、数据去向、配置状态和最近错误。
- Agent 对话创建保留草稿审核；模板提供“资料整理、网页创作、代码检查、周期检查”等固定可测样例。
- MCP 提供连接测试、超时、认证失败、工具列表刷新及禁用入口；扩展更新不静默扩大授权。
- 多 Agent 保留为高级任务能力，展示角色、轮次、总预算及独立结果，结束时提供汇总证据。
- 扩展市场纳入本期：先完成安装/更新/卸载、来源和版本验证、权限预览；公共投稿与审核需有维护负责人后开放，不把不可运营的空市场当交付。

### F12 模型推荐、用量与预算

- 根据任务所需图片/工具/上下文能力给出模型建议；默认使用用户选定配置。
- 切换模型或执行端涉及不同数据接收方时提示，不能静默把内容发给新服务。
- 支持单任务 Token、时长、步骤和费用预算；明确软提示与硬停止区别。
- 价格有来源、币种、更新时间；未配置价格标记未知，不显示虚假零成本。
- 仪表盘呈现成功任务、用户反馈、模型用量和费用估算，支持导出。

### F13 远程执行与跨设备连续性

- 基于现有远程模块评估差距，提供执行端注册/配对、可用能力、断连状态和移除授权。
- M0 确定首个真实执行器宿主与部署方式，提供独立于手机连接的持久作业进程、认证、任务提交/查询/取消、日志与成果下载接口。同步传输、数据存储、配对撤销、升级运维明确归属；不以 SSH 会话存活代替作业持久化。
- 长任务可提交到用户配置的远程端，手机关闭不应终止远程已经接收的任务；本地任务不具备此保证。
- 同步任务状态、成果索引和用户选择的数据；设备 ID、版本、冲突策略及删除传播明确。
- 并发编辑不得自动覆盖；单任务执行拥有者采用租约/版本控制，避免双端重复执行。
- API Key 默认不跨设备同步；若提供凭证迁移，必须单独授权并加密。
- 验收：手机发起、桌面/远程完成、手机查看；断连重连后状态可收敛，撤销设备后不能继续访问。
- 撤销配对阻止后续服务访问与同步，不承诺远程擦除已经下载到其他设备的副本；对离线执行端的撤销传播和已有任务处理给出明确状态。

### F14 数据、更新与运营

- 统一数据维护入口协调前台/后台运行；备份、恢复、清库、迁移阻止旧运行晚到写入。
- 迁移覆盖历史会话、模型、项目、记忆、知识库、技能、定时任务和授权；升级不扩大旧授权。
- 自动备份有状态与失败提示，恢复演练用隔离数据；安装包回退与数据库降级分别说明。
- 更新提供完整性校验、版本兼容说明与失败恢复；沿用现有签名体系。
- 反馈可关联脱敏 runId/errorCode；遥测默认不上传原始聊天、图片、音频、Key 或文件正文。
- 本期建立每成功任务成本、可选托管服务成本和用户价值基线；商业化方案按实测数据评估，不把付费系统强加为助手使用前提。

### F15 实时多模态会话

- 从 F02/F03 扩展，支持用户主动开启相机或屏幕共享，并结合语音连续追问；始终显示当前输入源和停止共享按钮。
- 首版先完成“前台音频会话 + 按需采样画面”的真实路径，不把截图轮询宣传为全帧实时视频；服务商原生实时协议通过适配层接入并说明差异。
- 维护 frameId、采集时间、有效期及会话轮次；“左边那个”“刚才那个”需关联有效画面，不确定时重新取样或询问。
- 支持语音插话和纠正；分别处理停止音频播放、取消旧轮生成、停止工具执行，不能把打断播报当成工具已取消。
- 帧率/分辨率/上传频率有上限；暂停上传后不补传缓存画面。受保护画面和授权失效返回明确状态。
- 在 W01 验证目标设备、语音活动检测/回声处理、Android 采集生命周期、协议可用性；测量端到端延迟、耗电、发热、流量及模型成本，未达到预算则降采样并告知。
- 验收：相机/屏幕各完成一次连续指代问答；画面变化后不复用过期结论；插话、锁屏、断网和权限撤销能停止采集并保留对话。

### F16 具体应用连接与动作覆盖

- 在 F04 动作目录之上建立连接器，每个连接器列出平台/应用版本、账号范围、读取/写入能力、接口方式、授权、结果验证及撤销策略。
- 首批按用户常用应用选定至少 5 个具体应用或系统服务；M0 冻结名单与可交付动作。先验证日历、联系人、地图、文件、媒体，再按真实接口扩展邮件/消息。
- 日历支持空闲/冲突查询与事件操作；联系人支持同名消歧；地图传递明确目的地；文件支持用户选定范围内检索/分享；媒体按接口能力提供搜索/播放。每项能力需有独立支持标记，不把整个类别标记为全支持。
- 邮件/消息的读取、草稿和发送按接口授权分别开放。第三方应用只有分享/跳转接口时保留人工提交，界面标记“等待用户完成”。
- 账户选择、OAuth/令牌刷新（适用时）、权限过期、撤销和多账号隔离纳入实现；复用安全存储，不将令牌写入通用日志或模型上下文。
- 验收：每个首批连接器至少一个真实完整动作，含失败/撤销案例；只支持准备动作的连接器不得计入“自动执行成功”。

### F17 关联个人上下文

- 在 F09 上关联人物、事项、时间、文件、项目与用户确认的关系；先用现有数据库实现实体/引用关联，是否需要额外索引由测量决定。
- 来源分“用户明确陈述”“授权资料提取”“待确认推测”；推测不能自动升级为事实，也不能作为敏感动作的唯一对象依据。
- 临时事项有有效期；冲突信息保留来源和时间，必要时给出候选让用户选择。“上次那份方案”无法唯一定位时不自动选择并发送。
- 删除/更正传播到关联、检索索引和未来上下文；原始历史若仍保留，应防止同一已遗忘条目自动重新入库，并让用户了解删除范围。
- 验收：同名人物、同名文件、多项目及过期事项均能正确消歧；跨任务指代能定位真实对象，未经授权的资料不能参与召回。

### F18 可复用工作流

- 将自然语言目标生成可编辑工作流草稿，用户确认后保存；步骤包括触发、输入、条件、动作、人工检查点、超时、失败策略和输出。
- 编辑器采用适合手机的步骤列表与分支详情；提供变量引用校验、流程校验、试运行、版本、导入/导出、启停及历史。
- 试运行默认仅预览读取与动作计划；真实副作用仍走审批，不能以“测试”绕过。复制/导入流程不携带秘密和授权。
- 重用 F06 的运行与审批；已验证的确定步骤直接执行，需要理解的步骤才调用模型。流程更新不改变正在执行的版本。
- 对可补偿动作记录补偿方式；不可逆动作只能停止并说明结果，不提供虚假的整流程撤销。
- 验收：完成“指定资料 → 周报 → 邮件草稿 → 用户确认”的流程，覆盖条件分支、部分失败、人工接管、版本变更和停止。

### F19 可核查研究与持续更新

- 从搜索问答扩展为研究任务：先定义问题、时间范围、地域、输出格式与预算，再检索、提取证据、归纳与交付。
- 引用保存 URL、标题、发布时间（未知则标明）、查询时间及支撑结论的片段定位；对受限内容不伪装已阅读全文。
- 关键结论尽量核对独立来源，区分转载同源、冲突证据、推断和未核实事项；缺乏来源时降低确定性，不编造引用。
- 研究成果包含摘要、结论、证据表、局限、来源和导出；支持增量更新与版本差异，订阅更新复用 F10。
- 验收：固定可复现资料集验证引用正确性；再用真实网页测试不可达、内容变化与付费墙。过期或矛盾资料必须在结果中呈现。

### F20 可操作结果卡

- 在 F07 成果与 F06 任务上提供结构化结果卡：提醒改期/取消、日程调整、文件预览/分享、路线打开、工作流试运行、代码差异/恢复。
- 操作由已注册动作类型生成，不能执行模型任意生成的按钮命令。结果卡引用真实资源 ID、版本和当前状态。
- 点击前重新读取资源和权限；已过期、被删除、被其他设备更改的卡片刷新或提示冲突。重复点击采用幂等处理。
- 每个操作反馈准备中、待确认、成功或失败，支持返回关联任务；危险动作沿用统一审批。
- 验收：至少覆盖上述六类结果卡，包含资源失效、快速重复点击、权限撤销与跨设备状态变化。

### F21 执行中纠正与人工交接

- 运行期间接收“换一个联系人”“只处理最近一周”“修改预算”“暂停”“这步我来”等控制请求，明确与普通追加聊天区分。
- 先识别受影响步骤，在可停止边界暂停，生成新计划版本；保留仍有效的成果，重新确认对象或权限变化的步骤。
- 新指令与执行完成同时发生时以持久事件顺序处理；已发生的外部动作不假装撤回，说明需要补偿或人工处理。
- 人工完成步骤必须有用户确认或可验证证据，再继续下游；不能仅因用户离开页面就认定已完成。
- 验收：等待审批、工具执行中、提交已完成三个时机分别纠正；旧审批作废、旧回调不污染新计划、不重复执行副作用。

### F22 快速开始与自主配置

- 必交付：用途引导、可信配置模板/二维码导入、端点及模型能力检测、失败修复引导；模板不包含明文 Key，导入后显示数据接收方，由用户在本机录入秘密。
- 导入配置验证字段和协议，不能自动请求未经确认的端点；允许自定义/局域网端点，但应明确展示其地址与用途。
- 自带 Key、本地模型与自托管路径保持完整，核心本地资料功能无需注册。
- 提供托管适配接口与完整体验设计；是否实际开通公共托管服务须在 M0 根据预算、服务可用地区与运营负责人决定。启用后另需认证、额度、计费/成本上限、限流、故障降级和数据保留策略，并计入服务端工时。
- 不运营托管时，明确当前需要自行配置，提供演示和模板；不得宣传“零配置直接使用”。此决策仅针对新增运营方式，不削减其他功能工作包。
- 验收：新用户通过模板完成真实任务；无效端点、缺失密钥、不支持图片/工具时能正确引导；若启用托管，则额度耗尽和服务中断不能造成无限重试/超额承诺。

## 7. 技术实施设计

### 7.1 分层与模块接点

| 层 | 实施内容 | 优先复用位置 |
| --- | --- | --- |
| presentation | MobileShell、助手主页、语音面板、统一任务/成果视图 | `lib/presentation/chat/`、`jobs/`、`projects/`、`widgets/` |
| application | 助手请求编排、动作协调、任务恢复、语音会话、同步协调 | `run_controller`、`run_coordinator`、`approval_bridge`、`device_action_runner` |
| domain | 能力描述、设备动作结果、提醒、记忆来源、同步版本 | `lib/domain/` |
| infrastructure | ASR/TTS、Android Intent、助手服务、持久调度、同步传输 | `lib/infrastructure/`、`android/app/src/main/` |
| persistence | 兼容迁移、事件/检查点/成果关联、租约与去重 | `lib/infrastructure/database/`、`application/session_log/` |

以上新增名称是设计建议，不表示当前已有同名类。实现前检查现有抽象，避免新增第二套任务引擎或审批引擎。

### 7.2 统一请求与动作契约

AssistantRequest 至少包含 requestId、entryPoint、conversationId、输入类型、附件引用、用户选择的上下文、locale/timezone、权限快照。

权限快照只用于展示与审计；每次执行及恢复时必须重新检查实时系统授权、设备能力和动作票据。分享文件 URI 不能假定进程重启后仍可读取，需要校验持久授权或将必要内容复制到受控工作区，并规定清理时机。

DeviceAction 至少包含 actionId、taskId、类型、结构化参数、目标、能力版本、风险、审批摘要、幂等键、有效期。ActionResult 区分 prepared、executed、verified、failed、unknown，包含执行证据引用和可恢复性。

提醒至少包含本地日期时间、IANA 时区、重复规则、下次计划时间、通知授权状态与补发策略。运行记录同时保留 UTC 时间及展示所需时区。

持久事件至少包含 taskId、runId、attemptId、eventId、顺序号、执行端及结果码。UI 从同一状态源派生；通知、任务页、聊天卡不得各自推断成功。

### 7.3 一致性与恢复

- 普通问答可保留轻量会话；有执行步骤/提醒/成果的请求关联任务，不把每条聊天强制转成复杂任务。
- 执行前持久化动作意图，执行后存结果；重启遇到结果未知的副作用动作先核实，禁止默认重试。
- 审批绑定 actionId 与参数摘要，拒绝过期、重复、被修改的授权。
- 维护模式、租约和数据代次跨 isolate 生效；恢复完成后刷新内存状态。
- 远程执行和同步采用幂等提交及冲突检测；不将网络请求发出等同远端执行成功。
- 外部网页、图片 OCR、文件、记忆和 MCP 返回内容均为任务数据，不能借其中的指令扩大工具权限、改变授权对象或导出敏感数据；加入提示注入与恶意深链测试。Deep Link 只打开预览，不直接确认敏感动作。
- 锁屏入口默认隐藏敏感上下文；敏感动作需要解锁后核实对象与内容。用户明确设置的低风险通知审批可保留，不能沿用到新增高风险动作。

### 7.4 功能开关与兼容

导航、语音、系统助手、手机动作、成果中心和同步分别可开关，便于分批内测与关闭异常功能。关闭功能保留用户数据与旧入口可用性；功能开关不能替代数据库迁移回滚。

共享服务更改必须验证 Windows 关键链路。Android 原生依赖、权限、服务变更需要重新构建，不能只热重载。

### 7.5 新增能力契约与共享依赖

| 契约 | 最少字段/约束 | 复用位置与用途 |
| --- | --- | --- |
| RealtimeSession | sessionId、turnId、frameId、采集时间/有效期、来源、上传状态、音频状态 | 与 AssistantRequest 关联，避免旧画面与新指令错配 |
| ConnectorCapability | connectorId、账号引用、动作、版本、授权范围、验证方式 | 映射 DeviceAction；访问令牌只存安全存储 |

- 已有 Android 16 x86_64 模拟器：页面、导航、复杂状态和通用交互。
- 至少三台 ARM64 真机，覆盖不同厂商及中低/中高性能；具体 Android 版本以项目支持范围和目标用户设备确定，M0 冻结。
- 权限允许/拒绝/撤销，通知关闭，锁屏/解锁，Doze，进程终止与设备重启，弱网/离线/恢复。
- 区分普通进程回收、划掉最近任务和用户在设置中“强行停止”；分别记录调度/通知行为。强行停止后不承诺仍继续运行，重新打开时解释中断并重建允许恢复的状态。
- 数据集覆盖新用户、长会话、多项目、大量任务和迁移样本。
- Android 原生功能在真机验收；PRoot 只用 ARM64；Windows 执行受共享代码影响的关键回归。

## 11. 风险与处置

| 风险 | 早期验证 | 处置与完成定义 |
| --- | --- | --- |
| 厂商不开放预期助手入口 | W01 设备验证 | 公布支持矩阵；快捷入口保底，限制项单列决策 |
| 持续语音耗电/服务不可用 | ASR/TTS 原型和真机耗电 | 分离前台连续对话与后台唤醒，按设备启用 |
| 跨应用页面变化 | 固定应用版本任务集 | 标注支持版本、步骤核验、失败交还用户 |
| 渠道不接受执行方式 | 分发渠道与官方政策核对 | 更换执行路线；不得以用户同意替代渠道要求 |
| 后台被回收 | 锁屏/Doze/进程终止测试 | 持久状态、恢复、远程接力、真实中断提示 |
| 数据升级损坏 | 多版迁移与故障注入 | 备份、维护租约、补偿、隔离恢复演练 |
| 功能范围过大 | WBS 每周燃尽与依赖检查 | 调整资源/日期，明确范围变更记录 |
| 新 UI 损害专业能力 | 逐路由功能映射 | 每个旧入口有新位置，工作台链路回归 |
| 模型结果错误/虚假成功 | 工具回执和验证 | 任务完成以真实结果为准，无法验证则标识 |
| 同步泄露或覆盖 | 配对、撤销、冲突测试 | 最小同步、加密、冲突选择、禁止默认同步 Key |
| 实时多模态热/流量/成本过高 | 真机持续会话与采样对比 | 降采样、限时与明确降级，不隐藏上传 |
| 第三方接口缺失或变化 | 首批应用逐动作原型 | 支持矩阵和人工提交边界，接口失败不得伪装完成 |
| 自动关联错人/错文件 | 同名和过期样本 | 来源与消歧，不依赖推测直接执行敏感动作 |
| 纠正与旧工具回调竞争 | 延迟/乱序事件测试 | 计划版本隔离，核实既有副作用后再继续 |
| 快速接入演变成未预算的托管平台 | M0 运营与成本决策 | 必交付模板/检测，托管启用时补齐后端预算和责任 |

## 12. 发布门禁与交付物

完整大版本发布必须满足：

- W00–W21 均有交付记录，F01–F22 均有验收映射；新增能力不能仅有原型或空入口。

- 所有 P0/P1 严重缺陷关闭；功能优先级与缺陷严重等级分开管理。未覆盖和阻塞项均不得记为通过；超出冻结支持矩阵的限制独立披露，不在验收后临时缩小矩阵。
- 无已知数据丢失、授权绕过、重复副作用和虚假成功问题。
- 迁移、恢复、签名、更新校验、异常关闭开关经过验证。
- 系统限制列入设备支持表；未实现需求保持阻塞/未完成，不用替代方案自动冲销原需求。
- 旧功能迁移位置、权限用途、语音与数据流向、已知限制写入用户帮助。
- 内测、候选版、正式版依次发布；初期按测试群/发布渠道分批，而非假设已有远程灰度基础设施。
