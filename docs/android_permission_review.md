# Android permission review

Reviewed on 2026-09-26 against the current Android manifest and feature call sites.

| Feature | Permissions | Request point | Distribution note |
| --- | --- | --- | --- |
| Local workspaces | `READ_EXTERNAL_STORAGE` (through API 32), `WRITE_EXTERNAL_STORAGE` (through API 29), `MANAGE_EXTERNAL_STORAGE` | The workspace import flow explains all-files access, opens Settings, and rechecks on return. | Google Play requires a declaration and approval for all-files access; the app must show why the Storage Access Framework is insufficient for its core project editing workflow. |
| Personal data export | `READ_CONTACTS`, `READ_SMS`, `READ_CALL_LOG` | `DeviceBackupManager.exportPersonalData` requests only the selected category after the user starts export. | SMS and call-log access require a Play declaration and approval. The backup/restore exception is listed in policy, but this app's eligibility is determined by Play review. |
| Wi-Fi automation | `ACCESS_FINE_LOCATION`, `ACCESS_BACKGROUND_LOCATION` | The settings page asks after a Wi-Fi rule is created or when the user opens its permission action. Foreground location is requested first. | Background location requires a separate Play declaration and must be justified as core functionality. |
| APK install and app updates | `REQUEST_INSTALL_PACKAGES` | `MainActivity.installApk` opens the system's unknown-app-sources page only when installation is requested. | Google Play restricts this permission to approved core package-handling uses and disallows self-update through this permission. The current `UpdateService` uses `installApk` for self-update, so this build is **not ready for Google Play submission** without a Play-specific update path and permission decision. |
| Device controls | `WRITE_SETTINGS`, `ACCESS_NOTIFICATION_POLICY`, `PACKAGE_USAGE_STATS`, `WRITE_SECURE_SETTINGS`, `READ_LOGS` | Special-access pages are opened from the relevant device action or capabilities screen; protected permissions require Root/Shizuku or a system grant. | Keep these declarations tied to the documented device-control features. Verify the final merged manifest and Play declarations for the chosen distribution. |
| Foreground tasks and notifications | `FOREGROUND_SERVICE`, `FOREGROUND_SERVICE_DATA_SYNC`, `WAKE_LOCK`, `POST_NOTIFICATIONS`, `REQUEST_IGNORE_BATTERY_OPTIMIZATIONS` | Task and notification flows request the applicable runtime or special access when needed. | Foreground-service types and notification behavior must match the published feature description. |

`WRITE_EXTERNAL_STORAGE` is declared only through API 29 (Android 10). On Android 11 and later it grants no additional access, but on Android 10 and earlier it is the only way to write shared storage: `PrivilegeManager.allFilesAccess()` requires both READ and WRITE there, and `Permission.storage` only requests permissions declared in the manifest. Without it, shared-storage writes on those versions would need Shizuku or Root. The remaining high-risk permissions are used by existing features; removing them from this build would disable those features. A Google Play release needs its own policy review and approval before submission, especially for the self-update path.

Primary references: [Android storage behavior](https://developer.android.com/about/versions/11/privacy/storage), [Google Play all-files access](https://support.google.com/googleplay/android-developer/answer/10467955), [SMS and call-log policy](https://support.google.com/googleplay/android-developer/answer/10208820), [background location policy](https://support.google.com/googleplay/android-developer/answer/9799150), [install-packages policy](https://support.google.com/googleplay/android-developer/answer/16558241).
