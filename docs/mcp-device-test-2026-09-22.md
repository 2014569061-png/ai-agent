# Android 真机冒烟测试报告

日期：2026-09-22

## 结论

**授权范围内的真机冒烟测试已完成，核心短对话、分叉、分支编辑重发和空闲重启恢复可用；并非全项通过。**

发现两项可复现现象：新消息提示计数不正确，以及测试所用的深链接未实现预期的新建/预填行为。另记录历史回复的模型与耗时显示变化，尚未确认其产品预期。本轮没有修改应用代码，也没有声称这些问题已修复。

本轮主动提交了 **3 / 3 次**获准的短模型请求，均获得回复；不再追加请求。没有通过被测 Agent 执行工具、文件修改或终端命令。设备操作和证据采集使用外部 ADB / MCP，不属于被测 Agent 工具调用。

## 4. 问题与待确认项

### D1：短会话已全部可见，仍出现错误的新消息提示

**状态：已复现，未修复。建议优先处理。**

复现路径：打开独立测试会话 → 发送一条短提示 → 收到一条短回复 → 两条消息都位于屏幕上半部，仍出现“有 N 条新消息，点击回到底部”。

- A 完成后显示 2（13），分叉后也显示 2（15）。
- B 只有一问一答，却显示 4（24、25）；重启恢复 B 后又显示 2（26）。
- 早期空欢迎页也曾显示 1（02）。
- 13、25 的截图已人工查看，消息全部可见且下方有大量空白。
- 点击提示可清除（33），不能因此判定触发逻辑正常。

建议排查 `lib/presentation/chat/chat_page.dart` 中会话切换、首次布局和新消息计数/滚动状态的重置时机。尚未定位根因，不将“跨会话累加”写成已证实的实现原因。

### D2：测试深链接未完成预期的新建或文本预填

**状态：已观察到，未修复；需核对 Android 意图接收与路由。**

- 冷启动 `nexus://new-chat` 后恢复了旧会话，并未按测试预期打开空会话（01）。
- 运行中的应用收到带 URL 编码 `prompt` 的同类 VIEW 链接后，Android 返回投递成功，但输入框仍为空（10）。
- 对照的 ACTION_SEND 文本分享可以准确预填（11、23）。

这说明该测试路径未达到预期，不证明所有深链接均失效。未确认原因属于 Activity 意图、冷/热启动处理还是应用路由。相关源码位于 `lib/infrastructure/share/`。

### O1：历史恢复后回复元信息和运行统计显示变化

**状态：待确认设计预期，不作为正文丢失。**

原 A 切回后，回复标题从实际模型和 3.9s 变为 NEXUS AI，底部显示 0 步 / LLM 0ms（13 → 22）。B 重启后也出现类似变化（25 → 26）。正文仍在。需区分当前内存运行统计与应持久化的历史消息元信息，再决定是否修复。

此外，多个普通弹层的无障碍关闭标签为“关闭审批弹窗”，语义不匹配（如 30、31）；本轮未进行完整无障碍验收。
