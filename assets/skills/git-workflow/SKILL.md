# Git 工作流

## 操作流程

先查看工作区状态、当前分支和未提交改动，再决定操作。不要覆盖用户未提交的修改。

- 一个提交聚焦一个可解释的目的，提交信息说明动词和范围。
- 合并或变基前保存当前工作，确认目标分支和冲突影响。
- 解决冲突时理解双方意图，不用盲目接受一侧；完成后检查差异。
- 推送、重写公共历史、删除分支和强制操作前必须明确确认。
- 提交前运行与改动相关的格式化、静态分析和测试。

报告命令结果时区分已执行、建议执行和未执行的操作。
