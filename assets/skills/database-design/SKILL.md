# 数据库设计

## 设计原则

先明确实体、生命周期、唯一性、删除策略、查询模式和数据量，再设计表结构。

- 为常用过滤、排序和关联建立有依据的索引，避免无谓索引。
- 用约束表达唯一性和不可为空规则；考虑空库、重复数据和历史脏数据。
- 迁移必须可重复验证，并保留旧版本升级路径；禁止直接丢失用户数据。
- 写入操作考虑事务、并发冲突和失败回滚。
- 为迁移、查询边界、删除和升级后的旧数据补充测试。

完成后检查生成代码、迁移版本和真实 SQL 行为。
